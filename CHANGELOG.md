# Unreleased

## Added

- **`Feed<S, C>` and `createFeed(read, protocol)`** (`@kyneta/changefeed`). A function that reads a value and carries its `[CHANGEFEED]`: the one shape for a value you read by calling and observe through the protocol. `CallableChangefeed` is now `Changefeed & Feed`. `@kyneta/schema`'s ref flags and `@kyneta/exchange`'s settle terms, `docStatusFeed` and `writeRefusalFeed` are each a `Feed`.
- **Undo: selective, across documents, durable** (`@kyneta/schema`, `@kyneta/yjs-schema`, `@kyneta/loro-schema`, `@kyneta/exchange`, `@kyneta/react`). Undo reverses this peer's own operations as they now stand among everyone's: text a collaborator typed inside yours survives your undo, and a value, mark or place someone changed since is left alone.
  - **`Substrate.revertible`** records every local commit (Kyneta batches, and direct writes an editor binding makes to schema types) and reverts one as it now stands, returning the record that redoes it. Plain documents are a strict stack; Yjs records by item identity, on its public API only (`yjs-surface.test.ts` pins every call); Loro reads its own history, and what happened since by content. Restoring deleted content creates new items or containers, so a revert returns a remap and older records are rewritten through it. Each commit states its record's footprint (`RevertibleCommit.footprint`), the region the revert writes and reads: `footprintOf(schema, ops)` on Yjs and Loro, where the ops landed at the grain the document is stored, each path cut to its stable prefix (`Path.stablePrefix`, before its first list index), and `WHOLE_DOCUMENT` on plain; `footprintsOverlap` and `footprintUnion` compare and join them. `undoConformance` (`@kyneta/schema/testing`) runs the same scenarios on all three, live and after a reload. Ephemeral documents have no undo.
  - **`createUndoStack`** (`@kyneta/exchange`): one step per gesture across documents (`stack.gesture(fn)`), typing grouped by gap, word boundaries, caret jumps and switching between typing and deleting (`stack.typing(fn)`, `stack.follow(docId)`), a step nothing of which still stands skipped silently. A typing step never spans documents. Steps conflict by what they write: each part carries its record's footprint, so steps on different documents, different record keys or different texts commute, and a plain document's steps all conflict. `stack.undo({ docs })` and `stack.redo({ docs })` take the newest step that wrote any of `docs` and that no newer step conflicts with, even under steps that do not conflict with it, so one stack per tab serves every editor, and a step is never undone or redone from under one made on it. A new step clears the redo steps it conflicts with, and transitively those redone after a cleared one that conflict with it; a redo step that no longer stands clears the same way. `depth` bounds each list. `stack.top(direction, docs?)` is the step an undo or redo tries first, as a tracked read. The stack lives in a serialized document (`UndoDoc`), so with a Store it survives a reload, and one writer pops it; a write-ahead note makes a crash mid-undo finish on the next load without applying anything twice. The decisions are a pure program (`undoProgram`). An undo never creates a document: a step's documents are opened with `exchange.open`, and a part whose document is not held here (destroyed, here or by another runtime on the Store) does not stand.
  - **`useText(ref, { undo: stack })`** (`@kyneta/react`): Cmd/Ctrl+Z and `historyUndo` undo, Cmd/Ctrl+Shift+Z, Ctrl+Y and `historyRedo` redo, and the caret goes to what changed. `UndoTarget` is the structural interface a stack satisfies.
  - **`exchange.open(docId, bound)`** (`@kyneta/exchange`): the document if this exchange holds it (open, replicated, or in its Store), and `undefined` otherwise. `get` may create a document; `open` never creates, writes or announces one. A deferred document opens if the Store holds it, and otherwise stays deferred.
  - New pure helpers in `@kyneta/schema`: `rebaseChange`, `revertStep`, `planValueRestores`, `diffString`, `diffSequence`, `singleEdit`, `editOf`, `continuesStep`, `TYPING_GAP`, `jsonRecordCodec`.

- **`@kyneta/datalog` — the Datalog evaluator is now its own package.** Stratified, semi-naive and incremental; rules and facts in, derived facts out, as a batch (`evaluate`) or as deltas over a long-lived database (`createEvaluator`). Negation, aggregation, guards, a join index, and host-computed relations that rules reference by name. A host relation declares its arity alongside its inputs and version, and `analyzeArity` holds every mention of every predicate to one width — heads included — so a rule that writes or reads a relation at the wrong shape is a `ProgramError` rather than rows nothing ever matches. That check is exported: a consumer that generates rule heads can run it over what it generated before installing it. Ground facts are held to the same map at `step`, which refuses the whole delta rather than applying part of it. A compute element passed a wildcard argument is refused too — it could only ever drop every row. Host **functions are declared the way relations already were** — `functions: { upper: { arity: 1, version: "1", apply: args => … } }` rather than a bare `functions: { upper: args => … }` — so calling one with the wrong number of arguments is a link error instead of a `NaN` that spreads through the fixpoint, and `declarationErrors` can check a pack's function expectations as well as its relation ones. Registering a bare function throws at evaluator construction, naming it. It knows nothing about constraints, peers or realities — it was extracted from `@kyneta/perspective` because a game runtime evaluating it as a rules engine was using exactly this half and nothing else, and because the two halves want different release cadences. Depends only on `@kyneta/zset`.
- **`@kyneta/zset` — the DBSP ℤ-set type and algebra.** `ZSet<T> = ReadonlyMap<string, { element, weight }>` with no zero-weight entries and caller-supplied keys. Tier-0, zero dependencies, in the idiom of `@kyneta/changefeed` and `@kyneta/machine`. It is its own package rather than part of `@kyneta/datalog` because four of `@kyneta/perspective`'s incremental kernel stages use ℤ-sets and no Datalog; depending on a Datalog package for them would misstate the dependency. Two things to read before using it: `zsetPositive` is a filter and *not* DBSP `distinct` (unlike `@kyneta/index`'s same-named function), and `zsetAdd` is a group on weights only — a key collision keeps the second operand's element.
- **`DispatcherHandle.hold(fn)`** (`@kyneta/machine`). It runs `fn` with the dispatcher busy, so messages dispatched meanwhile drain in order when `fn` returns. If `fn` threw and the drain throws too, the drain's error carries `fn`'s as its `cause`.
- **Type guards for six symbol-keyed protocols** (`@kyneta/schema`). `hasSubstrate`, `hasBackingDoc`, `hasMigrationChain`, `hasPopulated` and `hasDeleted`, each with its `Has…` interface, following `hasChangefeed`'s established shape. `hasTransact` already existed. Reaching these slots previously meant `(x as any)[SYMBOL]` at each call site, which switched off checking for the whole expression rather than just the property access.
- **Per-kind schema guards** (`@kyneta/schema`). `isScalarSchema`, `isProductSchema`, `isSequenceSchema`, `isMapSchema`, `isSetSchema`, `isTreeSchema`, `isMovableSchema`, `isTextSchema`, `isCounterSchema` and `isRichTextSchema` narrow the `Schema` union on its `[KIND]` discriminant, as `isMapChange` and siblings already did for `ChangeBase`. There is deliberately no `isSumSchema`: three interfaces carry `[KIND]: "sum"`, so the discriminant alone does not identify one type.

- **`nth(xs, i)` and `lookup(map, key)`** (`@kyneta/datalog`). Under `noUncheckedIndexedAccess` an index or key the caller knows is present still reads as `T | undefined`; these return `T` and throw where a non-null assertion would have let `undefined` through. `perspective` uses them too. Non-null assertions are now a lint error repo-wide (`noNonNullAssertion`), as AGENTS.md already required.
- **`cachedSnapshot(build)`** (`@kyneta/changefeed`). One snapshot of mutable state: `get()` builds it on first read and returns the same value until `invalidate()`, called wherever the state mutates. The producer's half of the changefeed identity rule below.
- **`mapPayload`, `diffText`, `CoordinateTrie` and `Coordinate`** (`@kyneta/schema`). `mapPayload(change, f)` is the one definition of the values a change carries; `diffText` (moved from `@kyneta/react`, which re-exports it) takes an optional cursor hint; `CoordinateTrie` is a context's trie of coordinates (`ctx.trie`), and a `Coordinate` is one of them, which is its address.

- **`signalFeed`, `firstDefined` and `settableFeed`** (`@kyneta/changefeed`). `signalFeed(read, subscribe)` moves here from `@kyneta/exchange`. `firstDefined(...feeds)` answers the first feed that has an answer and notifies when any changes. `settableFeed(initial)` holds a value or follows another feed until the next `set`, and lets go of what it held; `Settable<T>` is its type.
- **`collectGarbage()` and `disposeConformance`** (`@kyneta/schema/testing`). `collectGarbage` forces a full collection and lets finalizers run, turning on `--expose-gc` at run time, so no test runner needs the flag (Node only). `disposeConformance` checks a backend's `dispose`: a held ref reads its last value, and everything that needs what was released throws `DocumentClosedError`.

## Changed

- **A destroyed document is released, and a ref that outlives it reads its last value and refuses writes** (`@kyneta/schema`, `@kyneta/loro-schema`, `@kyneta/yjs-schema`, `@kyneta/exchange`, `@kyneta/react`) (breaking).
  - **Documents are collected.** No document was ever collected before: the ref registry was module-level, and its held values reached their refs, and Loro's event bridge formed a cycle through wasm memory. Each coordinate trie now owns its registry, and Loro's bridge reaches its substrate only weakly, so a document nothing holds is collected, standalone or through an Exchange, with or without `dispose`.
  - **`ReplicaLike.dispose(reason?)`** releases everything native: Loro's `LoroDoc` (freed), Yjs's `Y.Doc` (destroyed), plain's op log, the ephemeral state tree. Afterwards every member throws `DocumentClosedError`, except a substrate's reads, which return σ as it last stood. A bring-your-own document (`createLoroSubstrate(doc)`, `createYjsSubstrate(doc)`) is only let go of, never freed. `upgrade(replica, schema)` takes the replica's native document, so the replica is closed. Every custom `ReplicaLike` must implement `dispose`.
  - **`exchange.destroy(docId)`, `reset()` and `shutdown()` close their documents.** Writes, `unwrap`/`[NATIVE]`, and `version`, `exportEntirety`, `exportSince` and `merge` on a closed document throw `DocumentClosedError`, as do a position, devtools history or undo record made before the close. `whenPersisted` on a document destroyed with unconfirmed own writes rejects with it, a document destroyed while loading rejects `whenHydrated` with it (it was "destroyed while loading"), and `whenSettled` rejects with it unless the document's peers had already answered.
  - **`WriteRefusal`, `DocumentClosedError` and `DocumentLoadingError`** (`@kyneta/schema`). `WriteRefusal` is the base of every refusal; `WriterRefusedError` (`@kyneta/exchange`) extends it. `DocumentLoadingError` replaces the "still loading" `Error` a stored `json` document threw before it loaded. A refusal carries no stack.
  - **Refusal is a feed on the context:** `ctx.refusal`, the first answer of the substrate's and the owner's. `createRef(schema, substrate, { refusal })` attaches the owner's. `HydrationHandle.refuse`, `beginUpgrade` and `SubstrateFactory.upgradeForHydration` are removed: who may write is the owner's decision.
  - **`writeRefusal(doc)` and `writeRefusalFeed(doc)` return `WriteRefusal | undefined`**, read from the document's context, so they report a loading `json` document's `DocumentLoadingError` and a closed document's `DocumentClosedError` too. `useWriteRefusal` (`@kyneta/react`) returns `WriteRefusal | undefined`: narrow with `instanceof WriterRefusedError` to read `.writer`.
  - **`signalFeed` is exported from `@kyneta/changefeed`**, no longer from `@kyneta/exchange`'s internals.
  - **`exchange.documents` and an undo stack's following update only the documents a change names**, not every document held.

- **The folds are the interpreters, and the two ref flags share one protocol** (`@kyneta/schema`, `@kyneta/exchange`) (breaking).
  - `plainInterpreter` is removed: use `createMaterializeInterpreter(plainValueResolver(value))`. `Writable<S>`, which nothing used, and `INTERPRETER`, a marker nothing read, are removed too.
  - `populatedFeed` passes `null` and `undefined` through, as `deletedFeed` did, so `useValue(populatedFeed(maybe))` works; any other value that is not a ref still throws. `deletedFeed(null)` is now `null`, not `undefined`.
  - `populatedFeed(ref)` and `deletedFeed(ref)` on a definite ref are typed `Feed<boolean>`, without `| undefined`.
  - `HasPopulated` and `HasDeleted` are `HasFlag<typeof POPULATED>` and `HasFlag<typeof DELETED>`.
  - `SettleTerm` is removed from `@kyneta/exchange`: a settle term is a `Feed<boolean>`.
  - `CallableRef` is removed from `@kyneta/react`: `useValue` takes a `Feed<unknown>`, or `null` or `undefined`. A `@kyneta/reactive` `Reactive<T>` is a `Feed<T>`, and `track` takes one.

- **A ref is its state, and what it does lives on one prototype per schema node** (`@kyneta/schema`) (breaking). Refs are one fixed construction (`createRef`), no longer a stack of interpreter layers.
  - **The composable layers are gone:** `withNavigation`, `withReadable`, `withAddressing`, `withCaching`, `withWritable`, `withChangefeed`, `withTracking`, the pre-built `navigation`, `readable`, `addressing`, `writable`, `observation` and `tracking` layers, the fluent builder (`interpret(schema, ctx).with(…).done()`, `InterpretBuilder`, `InterpreterLayer`), `bottomInterpreter` and the carrier lattice (`HasRead`, `HasNavigation`, `HasAddressing`, `HasCaching`, the `mark…` assertions and the brands), `RefContext`, `RefMode`, `RWRef`, `plainContext`, `frozenClone`, `hasPreparePipeline`, `addPrepareStage`, `PrepareStage`, `coordinatePath`, `resolveToAddressed`, `CoordinateNode` and `SequenceAddressTable`. `interpret(schema, interpreter, ctx, path?)` and `createInterpreter` stay, for folds over a schema (materialize, zero, validate).
  - **Methods need their ref.** A ref's members live on a prototype shared by every ref of its schema node, and read the ref's state through `this`. A member called without its ref throws: pass `(v) => ref.set(v)`, not `onChange={ref.set}`. Member types declare their `this`, so calling a detached member is a type error.
  - **Refs live while held.** A list item's, record entry's or tree node's ref is the same ref while something holds it, and is collected once nothing does; its coordinate goes too unless a subscriber, a `[DELETED]` listener or a ref below needs it. A dead entry nothing holds is not kept. A subscription outlives its ref.
  - **An op's path creates no coordinate,** and a population mark creates nothing an earlier mark implies, so merged ops no longer grow either trie. Memory per ref falls about thirteenfold: an entry ref from 6,328 to 462 bytes, a struct with its six fields from 35,117 to 2,624 bytes (`tests/bench/README.md`).
  - **A list's items are populated exactly when the list is:** `populated(item)` is now true for an item that arrived by insert, and for what is below it.
  - **`ReadableTreeRef` types what a tree ref does:** `.node(id)` is the node's ref (it was typed as a `ReadableTreeNode`), and `.has(id)` and `.ids()` are declared. `ReadableTreeRef`, `ReadableTreeNode` and `WritableTreeRef` are exported. The parallel surface interfaces (`KeyedNavigation`, `ListWriteOps`, `TreeReadable` and the rest) are gone: the ref types are the surface. `Path.isAddressed` is gone; test `instanceof AddressedPath`.
  - **`RawSegment` and `Address` are classes;** an address is its coordinate's node in the trie (`Coordinate`), and a list item's identity is its numeric id. `AddressedPath` is a parent path and one segment: build one with `AddressedPath.of(segments, trie)` or from `trie.root`.

- **`SubstratePrepare.afterBatch(outcome)`** (`@kyneta/schema`) (breaking, custom substrates). The end of an authored batch now receives its `BatchOutcome`: the ops that survived and their inverses, each an op at its op's path, paired, and whether it aborted. `AnnounceOptions` gains `source`, carried by a local announcement of a write a local caller asked the substrate to make natively.
- **`useText`'s and `attach`'s `undo` option** (`@kyneta/react`) is `UndoTarget | "prevent" | "browser"`. `"prevent"` stays the default.
- **Rich text is materialized with adjacent equal-mark spans merged** (`@kyneta/loro-schema`, `@kyneta/yjs-schema`). Loro could split them after a mark was removed, so a re-materialized shadow disagreed with the stepped one.
- **The Yjs backend's TECHNICAL.md says how to configure `Y.UndoManager`** (scope it to the root map, capture only `transaction.local`): with its defaults it records a peer's merged edits as undoable.
- **A read keeps its identity until what it read changes, and is frozen** (`@kyneta/schema`) (breaking). `ref()`, and a composite's `[CHANGEFEED].current`, return the same object until the node or something below it changes; a change rebuilds only the path to it and shares every unchanged subtree. Reads are deeply frozen, so mutating one throws; copy one (`structuredClone`) to mutate it. See "A read is the store's own frozen value" below for what a read is.
- **`Plain<S>` is readonly** (`@kyneta/schema`) (breaking). Sequences, movable lists and sets read as `readonly Plain<I>[]`, products and maps with `readonly` properties, so mutating a read is a type error too. As an input type it is more permissive; a `.json()` scalar keeps its declared type.
- **`ReactiveMap.current` is a snapshot, not the live map** (`@kyneta/changefeed`) (breaking). `.current`, `()` and `[CHANGEFEED].current` return one `Map`, the same until the map is mutated and a new one after — the changefeed identity rule, now stated in the protocol: `current` is the same value until the state changes. `exchange.peers`, `exchange.documents` and every `@kyneta/index` `Collection` inherit it, and `SecondaryIndex.current` is a snapshot typed `ReadonlyMap<string, ReadonlySet<string>>`. `Source.fromReactiveMap` keeps snapshots instead of copying them.
- **`Reactive.refresh(thunk)`** (`@kyneta/reactive`) (breaking). It takes the render's thunk and re-runs only when the thunk is a new function or a tracked dependency fired, so a value keeps its identity across renders that changed nothing. A thunk must be pure over its captures and its tracked reads.
- **Change constructors take their values `Owned`** (`@kyneta/schema`) (breaking). `sequenceChange`, `mapChange`, `mapClearChange`, `setOpChange` and `richTextChange` join `replaceChange`: a construction site states `own(value)` or `trustAsOwned(value)`. The brand now covers payloads typed `unknown` as well as objects.
- **`WritableContext.prepare` is a fixed pipeline** (`@kyneta/schema`) (breaking). It is no longer reassignable: it locates the path, completes an authored change, advances a list's addresses, applies the change, settles the coordinates it rewrote and marks what it populated, in that order. The writable context owns its tries (`ctx.trie`, `ctx.subscribers`) and calls each step itself.
- **`advanceAddresses` no longer marks the addresses it removes dead** (`@kyneta/schema`). It returns them, and the caller kills each with everything below it.
- **`expandMapOpsToLeaves` is `expandProductMapChanges`** (`@kyneta/schema`) (breaking). It splits a map change at a struct into one op per field it names — one level, not to leaves — defined as the change projected onto each field (`projectChange`), so the CRDT bridges and delivery share one definition. It expands exactly where the schema at the path is a struct: the root special case and the fallbacks for set, tree and paths the schema does not fit are gone, the last of which passes such an op through rather than expanding it. `deliveryConformance` gains a **Grain** invariant: a write to a field is a change at the field, never at its struct, on every substrate.
- **`diffText` moves to `@kyneta/schema`** (`@kyneta/react`). `@kyneta/react` re-exports it, so its import is unchanged.

- **A CRDT `advance` trims nothing where it cannot, instead of throwing** (`@kyneta/schema`, `@kyneta/yjs-schema`, `@kyneta/loro-schema`). New `planAdvance({ base, current, to })` decides what `advance(to)` must do under the `Replica` contract: throw only for a `to` beyond the current version, trim for one between the base and the current version, and nothing otherwise. A live Yjs or Loro substrate trims nothing (it cannot swap the native document its callers hold) and throws only beyond its version; Yjs and Loro replicas no longer throw for a target behind their base, and the Loro replica no longer attempts a shallow snapshot it cannot place.
- **Of the seats sharing one storage, at most one authors each serialized document** (`@kyneta/schema`, `@kyneta/exchange` and every store package) (breaking). A `json` document's identity is its lineage, which every writer extends at the same positions whatever its peer id, so two tabs over one IndexedDB database (or two processes over one Postgres schema) that both wrote one `json` document stored two different operations at one position, and the next load kept one of them.
  - **The store records the writer.** `Store.append` and `Store.compact` take a required `WriteOptions` (`{ authored }`); an authored write (one carrying the seat's own operations on a serialized document) claims an unclaimed document for the store's seat, and is refused with `WriterRefusedError` (carrying `writer`), changing nothing, when another seat is recorded. Unauthored writes, which only persist what the network sent, never claim. `Store.writerOf(docId)` reads the record. `delete` is refused when another seat is the writer; a reader's `destroy()` evicts the document locally, leaves the writer's copy, and reports the refusal to `onStoreError`. Only pooled stores record a writer (in-memory, IndexedDB, Postgres); SQLite and LevelDB have one owner, so the rule holds by construction, and Prisma's session seats cannot be recorded, so route serialized writes to one process there.
  - **A seat that loads a document another seat writes is refused**: authored writes throw synchronously, naming the rule and the writer. A seat that lost a race (both wrote before either claimed) is rolled back from storage before anything of its write leaves the process, and asks its peers again from the rebuilt version (new sync input `sync/doc-reset`, and `RuntimeHooks.onDocReset`). New `writeRefusal(doc)` and `writeRefusalFeed(doc)` report the refusal, for good in the session; `persistenceError` keeps its meaning.
  - **Writership moves only with the seat**: when the writer's holder dies, the next Runtime to take its seat is the writer.
  - **Postgres needs a `writer` column**: `ALTER TABLE kyneta_doc_meta ADD COLUMN writer TEXT;`. `createPostgresStore` refuses a schema without it and names the migration; `postgresSchema()` and `schema.sql` include it. `@kyneta/postgres-store/testing` exports `pgResetTables`, which the suites use to recreate their tables from the current schema. No store format changes.
  - **Custom substrates**: `HydrationHandle` gains `refuse(reason)`, which makes authored writes throw from then on. New `beginUpgrade(factory, replica, schema)` returns the same handle over an already-loaded replica, backed by the optional `SubstrateFactory.upgradeForHydration`. A serialized substrate must implement both `createForHydration` and `upgradeForHydration`; Yjs and Loro's `refuse` throws, since concurrent writers have no single writer. Plain's `createPlainSubstrate` takes an `Authoring` (the reason writes are refused, or `null`) in place of `canAuthor`.
  - `@kyneta/exchange/testing` exports `UNAUTHORED` and `AUTHORED`, and the conformance suite's pooled seat section checks the writer record.
  - `Runtime.flush()` and `shutdown()` wait until both tracked work and the store are quiet, since each can start the other.
  - **`@kyneta/react`: `useText` keeps its field read-only while the document refuses this peer's writes**, as it already does while the document loads; the writer's edits still arrive, and a lost race's typing is rolled back in the field. New `useWriteRefusal(doc)` returns the refusal for any other editor, and `WriterRefusedError` is re-exported. `attach`'s `AttachOptions` gains `refusal`, a changefeed of the reason edits are refused.

- **Stores issue durable seats from a locked, fenced pool** (`@kyneta/exchange` and every store package) (breaking). Every restart of a stored Runtime was a new identity: one more version-vector entry per CRDT document it wrote, a new peer in every peer list, and a `Line` to it that stopped working. A store holds the state that proves a seat's history, and since store-first nothing leaves the process before the store has it, so a store can issue a seat that survives the process, if no two live writers hold it.
  - **`Store.seat` is required**: the seat the store issued when it opened, released by `close()` or by the platform when the holder dies. A Runtime with a store takes it (`Runtime.seat`, `peerId`); one without mints a session seat. Seats come in three kinds (`SessionSeat`, `OwnedSeat`, `PooledSeat`), and store packages build on `sessionSeat`, `parseSeatPool`, `allocateSeat`, `assertSeatHeld`, `planStoreOpen` and `STORE_META_SEATS_KEY`, all exported.
  - **Pooled stores** (in-memory, IndexedDB, Postgres) keep a pool of seats in their store-wide metadata; each open takes the oldest seat no one holds, so a reload keeps its seat, two tabs or processes open at once hold different ones, and the pool never exceeds the most writers open at once. IndexedDB holds seats with Web Locks (`createIndexedDBStore(name, { locks })`; without Web Locks it warns once and issues a fresh seat per open); Postgres with session-level advisory locks in the two-key space.
  - **Writes are fenced.** Each claim of a pooled seat increments its fence, and every write checks it in its own transaction, so a late write from a holder whose seat was taken again fails with `SeatLostError` and changes nothing. Losing the seat is final and store-wide: `onStoreError` fires once, nothing more is written or retried, `persistenceError(doc)` reports it for every stored document, including those opened later, and `flush()` resolves. Recover by opening a new store (in a browser, reload).
  - **Store formats bump minor to 1.1** (IndexedDB, LevelDB, and SQLite, Postgres and Prisma together through `sql-store-core`; Prisma writes no pool, so the bump is harmless there). Older stores read as an empty pool.
  - **`InMemoryStoreData` gains `seats`**; build it with `createInMemoryStoreData()`. A closed `InMemoryStore`, like every store now, refuses every operation, so reopen a store over the same `sharedData` to model a restart. `abandonSeat(store)` (`@kyneta/exchange/testing`) releases a seat without closing, as a dying holder's platform would.
  - **Postgres needs a connection per open store**: `PgAdapter` gains `dedicated()`, which `fromPool` (a checked-out client) and `fromClient` (the client itself) implement, and which holds the seat lock until `close()`. `PostgresStore`'s constructor is private: open with `PostgresStore.open` or `createPostgresStore`, and close stores before `pool.end()`.
  - **SQLite is single-owner**: one `SqliteAdapter` owns its database. `fromBetterSqlite3(db, { busyTimeout? })` and `fromBunSqlite` take `PRAGMA locking_mode = EXCLUSIVE` and the file lock when they wrap the connection, and a second adapter over the file waits `busyTimeout` (default 5 s) and is refused. `SqliteAdapter.transaction` is a plain transaction again, no longer required to take the write lock at its start (`.immediate()` is gone), and the store sets no pragma. A Durable Object's adapter takes no lock. Its seat, like LevelDB's, is `owned`: one per database, reused on every open, unfenced. A fleet of processes over one database is what Postgres is for.
  - **Prisma issues a session seat per open**, since it cannot hold a lock for a store's lifetime: one version-vector entry per process start per document written. Its constructor is private (`PrismaStore.open`), and a write that loses its `seq` to another store is tried again until it does not, rather than once.
  - `LevelDBStore`'s constructor is private: open with `LevelDBStore.open` or `createLevelDBStore`.
  - **A `Line` to a stored peer survives its restart**: the peer returns with its seat and the `Line` resumes, nothing lost or delivered twice. A `Line` now reads its cursors only once its stored documents have loaded (it re-delivered every stored message after a restart), and a message sent before then is written once they have (it threw "still loading").
  - The conformance suite's `seats` declaration (`pooled` with `abandon`, `owned`, or `session`) replaces `secondInstance`, and is required. Its fault-injection properties sweep every step of a write, so `makeArmedFault` returns `fired()` and a `faultFactory` result exposes it.
- **`@kyneta/postgres-store`: `doc_id` columns must be `COLLATE "C"`** (breaking, operators). `listDocIds(prefix)` returned nothing under a locale collation such as `en_US.utf8`, the default almost everywhere, because its range scan assumes code-point order. `createPostgresStore` now refuses a `doc_id` column without `COLLATE "C"`, and its error gives the fix: `ALTER TABLE kyneta_doc_meta ALTER COLUMN doc_id TYPE TEXT COLLATE "C";` and the same for `kyneta_records`. `schema.sql` declares it, and `postgresSchema(tables?)` returns the canonical DDL for any table names. `@kyneta/postgres-store/testing` exports `pgTestServer()` and `pgTestDatabase(name)`, which give a test suite a database of its own on the `KYNETA_PG_URL` server.
- **`listDocIds(prefix)` returns exactly the ids starting with `prefix`, on every store** (`@kyneta/sqlite-store`, `@kyneta/leveldb-store`, `@kyneta/indexeddb-store`, `@kyneta/prisma-store`). SQLite's `LIKE` ignored ASCII case (`users/` returned `Users/Bob`) and scanned the whole table. LevelDB's upper bound `prefix + "\xff"` left out every id continuing with a character from U+0100 on (`p/ālice`, `p/日本`), and its store-format probe could miss existing documents the same way. IndexedDB's `prefix + "\uffff"` left out an id continuing with U+FFFF. Each now scans `[prefix, prefixSuccessor(prefix, order))`, a new `@kyneta/exchange` export. Prisma narrows with `startsWith` and keeps exact matches itself; on MySQL, `doc_id` needs a binary collation (`utf8mb4_bin`), as its README now says.
- **A peer names its principal, and the Runtime issues its own peer id** (`@kyneta/transport`, `@kyneta/wire`, `@kyneta/exchange`, `@kyneta/react`, `@kyneta/random`) (breaking). The caller chose the peer id, and a CRDT needs a guarantee the caller cannot give: a replica may write under an id only if no other live replica writes under it and it holds everything ever written under it. A store-less page that reloaded with its old id, or a duplicated tab sharing one through `sessionStorage`, broke that, and the replicas reached equal version vectors over different contents and never synced again.
  - `new Exchange({ principal, type? })` replaces `id`. The principal is who the peer says it is: several Exchanges may share one, it is carried in `establish`, and it is not verified. `PeerIdentityDetails` is `{ peerId, principal, type }`; `name` and `PeerIdentityInput` are gone, and `PeerType` is exported. `ExchangeNetworkParams`, for wrapping a Runtime, takes the same two fields.
  - The peer id is a seat: every Runtime issues itself a fresh one, `randomPeerId()`, now 128 bits. `RuntimeParams.peerId` is gone; `new Runtime()` constructs. Without a store a seat changes every session: each session that writes a CRDT document adds one version-vector entry, and peer lists see a new peer per session. With a store, see durable seats above.
  - Key policies on `principal` where they mean who (`p => p.principal === "my-server"`), and on `peerId` where they mean which replica. `exchange.peers` stays keyed by seat.
  - `whenPeer(exchange, predicate)` resolves with the first connected peer matching `predicate`, including one in its grace period. A `Line` is addressed by seat: find the server's with `whenPeer`, then `Chat.sender(exchange, server.peerId)`. Two Exchanges for one principal now write two outboxes, so React StrictMode's double mount no longer loses a message.
  - A `Line` to a store-less server does not survive its restart: the restarted server is a new seat, and clients open new `Line`s to it (with a store, it survives; see durable seats above). `Line` documents to a seat that never returns stay stored on its peer.
  - `persistentPeerId`, `releasePeerId`, `resolveLease`, `LeaseState` and `LeaseDecision` are removed. Pass a principal instead.
  - `useExchangeSingleton(principal, factory)` keys on the principal, and `factory` may return a promise. The hook returns `null` until it resolves. `ExchangeProvider` warns when the Exchange changes for the same principal: it wastes a connection, and no longer corrupts anything.
  - The `duplicate-peer` diagnostic is removed: with issued seats, a second channel for a connected seat is one peer on several transports, which is supported, and it logged an error for it. A Runtime refuses a second Exchange (`setHooks` throws), since two Exchanges over one Runtime would share its seat.
- **CRDT peer ids use the full width each backend allows** (`@kyneta/schema`, `@kyneta/yjs-schema`, `@kyneta/loro-schema`) (breaking). A Yjs `clientID` was a 32-bit hash of the peer id, which gives a ~1% chance of two peers colliding at about 9,300 peers, and a collision silently drops one of every pair of operations the two write at the same address, on every document they share. It is now 53 bits, and a Loro `PeerID` is 64 bits rather than 53. Both come from the new `peerNumber` in `@kyneta/schema` (FNV-1a-64 over UTF-8 bytes), and a Yjs `clientID` is always the low 53 bits of the Loro `PeerID` for the same peer id. Every peer id maps to a new number once: existing documents keep their history under the old number and the peer continues under the new one, which adds one version-vector entry per peer per document. Code that recomputes native peer numbers from peer ids, such as a copy of the removed `hashPeerId`, imports `yjsClientId` (`@kyneta/yjs-schema`) or `loroPeerId` (`@kyneta/loro-schema`) instead.
- **One store per Runtime, and a storage several stores open safely** (`@kyneta/exchange` and every store package) (breaking). Several instances may open one storage: tabs over one IndexedDB database, processes over one Postgres schema, Runtimes over one in-memory `sharedData`. Three things broke there. A compaction deleted every record of the document, including ones another instance had appended and it had never read. The SQL stores numbered records from an in-memory counter per instance, so two instances collided on the `(doc_id, seq)` key. And loading depended on the order of records no single writer chose.
  - `ExchangeParams.store` and `RuntimeParams.store` take one `Store`, replacing `stores: Store[]` and its first-hit reads and fanned-out writes.
  - `Store.replace` is replaced by `mark(docId)` and `compact(docId, records, through)`, which deletes only the records at or before a mark the caller took before reading, and appends after the rest. A compaction takes everything it read into the live replica before it deletes it, and pushes to peers what it took in. One it cannot take everything into appends instead.
  - Record positions come from the storage: IndexedDB's autoincrement key, and for the SQL stores `MAX(seq) + 1` read inside the write transaction, under a Postgres advisory lock or, for Prisma, a retry on a collision. (SQLite's multi-instance support added here, through `BEGIN IMMEDIATE`, was withdrawn by durable seats: a SQLite database has one owner.) `SeqNoTracker` moves into `@kyneta/leveldb-store`, whose directory lock makes it sound, and is no longer exported from `@kyneta/exchange`.
  - Loading does not depend on record order, and never enters a superseded lineage (`latestLineage` in `@kyneta/schema`). The confirmed version after a load joins only the entries the replica reaches.
  - `RuntimeHooks.onDocLocalChange` is `onDocAdvanced`, `Synchronizer.notifyLocalChange` is `notifyAdvanced`, and the sync input `sync/local-doc-change` is `sync/doc-advanced`: a compaction's merge advances the replica off the network too.
  - `createInMemoryStoreData` and `recordsOf` build and read in-memory storage. (The conformance suite's `secondInstance` option added here became `seats` with durable seats.) `InMemoryStoreData.records` holds each record with its mark.
- **Two lineages of a plain document converge on the later one, and say so** (`@kyneta/schema`, `@kyneta/exchange`) (breaking). A `json` document's lineage is minted by its first write. Two meet when a writer restarts without its store, or when two writers author one document. Every peer used to reset to the other's lineage, so both reset and the replicas swapped, permanently; the restart case the design meant to serve, a writer writing straight after `get()`, ended with the server on the new state and the writer on the old. And a peer asking for a whole document across the boundary could quote a genesis cursor, be answered with a delta, and ask again until the process ran out of memory.
  - Lineages are minted time-ordered (`mintLineage`), and every peer crosses only toward the lineage minted later (`supersedes`). The peer holding the later lineage takes nothing and sends the other its whole document. Order is by wall clock: a writer whose clock is behind the lineage it replaces loses. Lineages stored before compare in an arbitrary order.
  - Every crossing reports a `lineage-collision` diagnostic, severity `error`, carrying both lineages. The writes of the superseded lineage are gone.
  - Asking for a whole document across a lineage boundary quotes no cursor, so the answer is the whole document.
  - A store-backed document that reset away from an unconfirmed own write publishes again.
- **With a store, an own write reaches peers only once the store has confirmed it** (`@kyneta/exchange`) (breaking). A push used to leave before the store write that recorded it. A crash in between left writes only the network had; the next session reloaded without them, wrote new operations at the addresses they occupy, and peers deduplicated the new operations away. The divergence was permanent and silent on Yjs, Loro and plain. Now no offer of a document leaves, whether a push, a relay or an answer to an `interest`, while the document has own writes its store has not confirmed, and the withheld offers are sent when it does. Own writes reach peers one store write later. Without a store nothing changes.
  - New `persisted(doc)`, `persistedFeed(doc)`, `whenPersisted(doc)` and `persistenceError(doc)` report whether a document's own writes are confirmed, and why not.
  - A failed store write is retried on its own, 250 ms after the failure and doubling to 30 s, rather than on the next mutation. A document waiting to retry does not hold up `flush()` or `shutdown()`.
  - `PeerDocSyncState` gains `offerOwed`, and `ourVersionTheyWillHold` moves when an offer is reported sent rather than when it is emitted. An `interest` clears it until its answer is sent.
  - An `interest` whose version does not parse is answered with the whole document rather than ignored.
- **`Substrate.commitPending()` is required** (`@kyneta/schema`) (breaking, custom substrates). It commits whatever the native document holds uncommitted, so `subscribeLocalUpdates` reports a pending write before an export sends it. A substrate whose native document never holds a write pending implements it as a no-op. `deliveryConformance` checks it, and an environment can supply a `pendingNativeWrite` driver to check a pending write is reported.
- **New sync message `accept`, and `offer` loses `reciprocate`** (`@kyneta/transport`, `@kyneta/wire`, `@kyneta/exchange`) (breaking). The protocol version is `2.0`, and a peer that omits it is read as `1.0`. Mixed-version meshes are not supported. `establish` in `2.0` also carries the peer's principal, `pr`, and drops `n` (name); a `1.x` `establish` without `pr` still parses, so its version mismatch is reported.
- **Plain payloads carry their log position, and the plain replica type is `["plain", 2, 0]`** (`@kyneta/schema`) (breaking). Stored `json` documents from earlier versions are refused on load.
- **`resetFromEntirety` takes only the payload, and `ReplicaFactory` declares `historyFree`** (`@kyneta/schema`) (breaking, custom substrates). Whether a merged payload was taken in is whether the replica's version then reaches the version it was offered at (`reaches`).
- **`Version.join` and `reaches`** (`@kyneta/schema`) (breaking, custom substrates). Every version type implements the least upper bound, with the lattice laws `versionConformance` (`@kyneta/schema/testing`) checks; `reaches(ours, theirs)` is the one test of holding a version.
- **`PeerDocSyncState` replaces `lastKnownVersion` with `ourVersionTheyHold`, `ourVersionTheyWillHold` and `theirVersionWeHold`, beside `status`** (`@kyneta/exchange`) (breaking). Each push to a peer starts from `ourVersionTheyWillHold`.
- **The Yjs replica type is `["yjs", 2, 0]`, and a Yjs version is its state vector** (`@kyneta/yjs-schema`) (breaking). Stores and peers from before do not load or sync. The Yjs substrate writes a `kyneta.clock` top-level type (`DELETE_CLOCK`), so that every change, a delete included, advances the state vector.
- **A native local write is delivered with `replay: false`** (`@kyneta/schema`, `@kyneta/yjs-schema`, `@kyneta/loro-schema`) (breaking for subscribers that treated every bridged write as remote). `replay` is true iff no writer on this peer made the ops: a merge, a reset or a decay tick. A write on the native document that the event bridge reports, an editor binding's for instance, was made here.
  - `ctx.announce(ops, { origin, local })` takes a required `local` (`AnnounceOptions`), and the `announce` variant of `BatchOptions` carries it (breaking, custom substrates).
  - `Substrate` gains the required `subscribeLocalUpdates(listener)`, which fires for every local write however it was made (breaking, custom substrates).
  - The Yjs own-commit mark is per substrate, so a second substrate over one `Y.Doc` announces the first's batches as native local writes.
- **A Yjs merge without an origin reports `origin: undefined`** (`@kyneta/yjs-schema`), as Loro and plain do. The invented `"remote"` label is gone from `Changeset.origin` and from `transaction.origin`.
- **`DocReadyInfo` is discriminated by mode** (`@kyneta/exchange`). For an interpreted document, `replica` is typed as the `Substrate`. It is the one record of a registered document: the Synchronizer holds the Runtime's own object, read-only.
- **`Synchronizer.notifyAdvanced` (formerly `notifyLocalChange`) is no longer a workaround for `unwrap` writes** (`@kyneta/exchange`). Native writes are picked up automatically, so remove manual calls.
- **Replacing or clearing a whole `ephemeral` record removes older keys the writer had not seen** (`@kyneta/schema`) (breaking). Writing a record whole, or `record.clear()`, is now last-writer-wins on the record: every key written before it goes, including ones still on their way to this peer. Previously only the keys the writer held were removed. The per-key calls, `.set(k, v)` and `.delete(k)`, touch nothing else. Presence code that means "this peer's entry" should use them.
- **`MapChange` gains `clear`, and `record.clear()` sends it** (`@kyneta/schema`) (breaking, custom substrates). `clear()` used to list the keys the local peer held and delete each one. It now dispatches `mapClearChange()`, an intent that each substrate's merge law resolves: Loro, Yjs and plain remove the keys they hold, exactly as before, and `ephemeral` also removes older entries still in flight. It is sent even when the record looks empty, which is what lets `ephemeral` clear entries that have not arrived yet. A custom substrate must honour `clear`; `mapChangeEffects(change, heldKeys)` does the work, and `tests/conformance` now declares each substrate's reach as `clearReach`.
- **`lastUpdated` returns `null` for an `ephemeral` field nobody has written** (`@kyneta/schema`) (breaking). It returned `0`, because the substrate stored a zero at timestamp 0 for every declared field. The tree now holds only what was written, and the zeros a read returns come from the projection, so there is no timestamp to report.
- **`ephemeral` wire format** (`@kyneta/schema`) (breaking). A key deleted or written whole travels as a horizon, `[content, horizon, deleted]`. A deleted scalar is `[null, horizon, true]`, the same bytes as before; a deleted or cleared container shrinks from one tuple per leaf to one tuple. Structural zeros are no longer stored or shipped. Mixed-version meshes are not supported.

- **`ephemeral` sync ships what changed** (`@kyneta/schema`, `@kyneta/exchange`) (breaking). Every update resent the whole document: a one-leaf change on a 200-peer presence roster cost 7 895 bytes. It now costs 150, and stays flat as the roster grows — 148 bytes at five peers. Each leaf carries a local install ordinal, so `exportSince` can answer "what have I taken in since?", and a digest of the replicated state travels beside the version so two peers that already agree can say so. A wall-clock version could never say it: two peers writing different fields in the same millisecond share a timestamp over divergent trees. A peer that misses an update is now repaired with a targeted delta (1 212 bytes, of which 43 is the delta) rather than a full resend (9 015). **The wire format is unchanged** — the install ordinal is stripped on the way out, which puts the tombstone marker back where peers already expect it.
- **The `Delivery` sync-mode axis is removed** (`@kyneta/schema`, `@kyneta/exchange`) (breaking). `SyncMode` had three axes; `delivery` separated substrates that could compute a delta from those that could only send a snapshot, and `SYNC_EPHEMERAL` was the only `"snapshot-only"` one. Now that it sends deltas the axis has one value and discriminates nothing. `SyncMode` is `{ writerModel, durability }`, the `Delivery` type is gone, and `requiresBidirectionalSync(mode)` is `mode.writerModel === "concurrent"` — so ephemeral documents now exchange bidirectionally, which is how a peer asks for what it missed. **A `SyncMode` literal that names `delivery` will not compile.** Drop the field; the two sites that read it wanted `durability`.
- **`Replica.exportSince` distinguishes "cannot serve" from "nothing to send"** (`@kyneta/schema`) (breaking, custom substrates). `null` means the cursor cannot be served — history trimmed past it, or an epoch this replica did not mint — and the caller answers it with a whole document. A peer that is merely current must get an empty delta instead. A custom substrate returning `null` for an up-to-date cursor will send an entirety to every peer it already agrees with.


- **`@kyneta/perspective`'s barrel exports only what the package owns** (breaking). It no longer re-exports the Datalog language and evaluator (`Rule`, `Atom`, `Value`, `evaluate`, `createEvaluator`, `stratify`, `Host`, …), the ℤ-set algebra (`ZSet`, `zsetAdd`, …), or `Result`/`ok`/`err`. Import those from `@kyneta/datalog` and `@kyneta/zset`, both of which perspective declares as dependencies, so an install already has them. The kernel surface — `createReality`, `solve`, `Constraint`, `Reality`, the producers, the version-vector and authority helpers — is unchanged. **`createIncrementalPipelineFromBootstrap(result)` is now `createIncrementalPipelineFromStore(result.store, result.config)`**: the kernel had been importing a bootstrap type for a function that only ever read those two fields, which pointed a dependency backwards.
- **The `Value` domain moved to `@kyneta/datalog` and is declared structurally.** The spec's `ref(CnId)` (§3) is now `{ ref: ValueRef }` where `ValueRef` is `{ peer: string; counter: number }` — the same shape as perspective's `CnId`, so a reference is a Datalog value with no conversion and no import in either direction. Every serialized key is byte-identical, so nothing that sorts or snapshots by fact keys moves. The union stays closed and compiler-checked: an open, host-registered value domain was designed and benchmarked, and the numbers are recorded in `packages/datalog/TECHNICAL.md` rather than the mechanism being built speculatively.
- **`extractPartitionKey` and `Stratum.partitionKey` are gone** (`@kyneta/datalog`). The partition-key analysis ran on every stratification — so on every `createEvaluator` and every `changeRules` — and nothing read the result; the phases of the partitioned-evaluation plan that would have read it were never started. Its theory is intact in `packages/perspective/theory/partitioned-settling.md`, to be rebuilt alongside its first consumer. `evaluateAggregationForSubs`, also exported and referenced only by its own tests, went with it.

- **One `batch()` now reaches a subscriber as one `Changeset`** (`@kyneta/schema`). A deep subscriber — the facade `subscribe`, as opposed to `subscribeNode` — used to be called once per *changed path*, so a batch writing four fields woke a root subscriber four times. That made a subscriber's callback count depend on how many paths the writer's batch happened to touch, which is an internal detail of the writer, and it left no way to observe a batch as a unit: `Changeset` has no batch identifier, and `origin` is an optional caller-supplied label that correlates nothing unless the writer cooperates. A subscriber now receives one changeset per transaction covering everything written inside its own subtree. `subscribeNode` is unaffected, and no subscriber hears about anything it did not hear about before — delivery narrows, never widens. The behaviour matches what this package's TECHNICAL.md has described, worked example included, since the descendant-delivery rewrite; that example now runs as a test. **If you counted callbacks, or relied on each changeset holding a single path, read `changeset.changes` instead.**
- **A changeset's `changes` are in dispatch order** (`@kyneta/schema`). Grouping by path used to reorder them: an ancestor write landing between two writes to the same descendant floated past both, so relaying a root subscription onward through `applyChanges` replayed a log that reached a different state than the writes produced. A root subscriber's `changes` are now exactly the `Op[]` that `batch()` returned, filtered to its subtree.
- **Delivery order between the two channels** (`@kyneta/schema`). Own-path and deep callbacks used to interleave per changed path; every own-path callback now fires before every deep callback. Deep subscribers are still called deepest-first. Planning the whole flush before firing any callback is what collapses a subscriber's several changesets into one, and this ordering is the consequence.
- **Incoming sync merges deliver far fewer changesets** (`@kyneta/exchange`, `@kyneta/react`, `@kyneta/devtools`). A merge flushes once for its whole payload, so an `offer` touching fifty paths previously delivered fifty changesets to every document-root subscriber and now delivers one. No semantic change for these packages — the exchange reads `changeset.replay`, which rides unchanged, and `@kyneta/reactive` discards the payload entirely — but devtools output is correspondingly less noisy.

- **A `canShare` policy that returns `false` as a catch-all now blocks more than it used to** (`@kyneta/exchange`). Because denial now covers direct requests, a policy that vetoes documents it does not actually govern will block by-id fetches of those documents — including `Line`'s outbox and inbox, which are fetched by id by design. Such a policy was only ever working through the gap fixed above. Return `undefined` for documents outside your policy's concern, which is what the three-valued logic is for; both README examples show the pattern.

- **Change constructors require an `Owned` payload** (`@kyneta/schema`). `replaceChange` now takes `Owned<T>` for object payloads, so a construction site must say whether it is handing over a copy (`own(value)`) or asserting nobody else holds the value (`trustAsOwned(value)`). This closes the other half of the aliasing problem: a caller that reuses the object it passed to `.set()` could previously rewrite what subscribers saw, with no write recorded and no changeset emitted. Primitive payloads are unbranded — nothing can hold a reference to one. `deepClonePlain` moved to its own module so `own` could sit beside the constructors it guards; its export path is unchanged.

- **`whenSettled` and `useDocReady` take `authority`, not `peer`** (`@kyneta/exchange`, `@kyneta/react`) (breaking). `peer` was a second spelling of an `authority` predicate; pass the same predicate as `authority`, which also accepts `"self"` and `"any"`.
- **Stored plain documents refuse writes until they have loaded** (`@kyneta/schema`, `@kyneta/exchange`) (breaking). A `json.bind` document in a Runtime or Exchange with a persistent store throws "still loading" on an authored write until loading completes. `await whenHydrated(doc)`, `whenSettled(doc)`, or seed with `initialize`. Such writes were previously overwritten by the loaded state, and forked the document's lineage. `createPlainSubstrate` takes a required `canAuthor` (`ALWAYS_AUTHOR` for a substrate that may write from the start).
- **`useText` binds after the document has loaded** (`@kyneta/react`). The element is `readOnly` until then, and shows the loaded text once bound. The adapter gains `attachWhenLoaded(element, textRef, loaded, options)` for the same outside React.
- **Readiness answers for any ref within a document** (`@kyneta/exchange`, `@kyneta/react`). `hydrated`, `whenHydrated`, `settled`, `whenSettled`, `docStatus` and the React status hooks previously reported a child ref as ready while its document was still loading. `sync(ref)` also accepts any ref within a document.
- **Changesets are delivered after the native commit** (`@kyneta/schema`, `@kyneta/loro-schema`, `@kyneta/yjs-schema`). Subscribers now run once the outermost block's Loro commit or Yjs transaction has closed, and still before `batch()` returns. A `batch()` issued from inside a subscriber is its own native commit with its own origin; previously Loro swapped the two blocks' origins, and Yjs folded both into one transaction. Changesets are delivered in the order their batches were sealed, so a merge inside a `batch()` body is delivered before that batch.
- **The writable context owns the batch lifecycle** (`@kyneta/schema`) (breaking, custom substrates). `WritableContext.flush(options)` is gone: the context plans and delivers each sealed batch itself; `announce` is a context method, `ctx.announce(ops, origin?)`, and the free function is gone; `runBatch` returns the authored ops its frame captured, and `FORWARD_OPS_MARKER` / `FORWARD_OPS_SINCE` are removed. Every `ctx.prepare` must happen inside `runBatch` or `announce`.
- **`YjsVersion.fromDeleteSet` is removed** (`@kyneta/yjs-schema`) (breaking). Use `YjsVersion.fromDoc`, which computes the same version.
- **Substrates announce only after λ and σ agree; batch provenance is a required `ingress`** (`@kyneta/schema`) (breaking, custom substrates). `SubstratePrepare` is now `prepare(path, change, recordInverse | null)`, `afterBatch()` and `runBatch(work, CommitOptions)`, and sees only local writes and their compensations (`recordInverse === null`). A substrate that takes in ops by any other route (a merge, a native event, a decay tick) brings its shadow up to date itself, then calls `ctx.announce(ops, origin)`, which never calls back into `prepare` or `afterBatch`. `executeBatch` is gone: substrates announce, and `applyChanges` opens its own `runBatch`. `BatchOptions` is a union over a required `ingress: "author" | "announce"`; `ctx.prepare` takes `PrepareOptions` (`"author" | "compensate" | "announce"`). `replay`, `projection`, `compensating` and `RECORD_INVERSE` are gone upstream, and `BatchOptions` no longer extends `BatchMetadata`. `CommitOptions` is now exported from `substrate.ts`, still from the package root. `Changeset.replay` means what it did for subscribers, except that it is now `false` rather than `undefined` for local writes.
- **`merge` and `resetFromEntirety` take `MergeOptions` (`{ origin? }`)** (`@kyneta/schema`) (breaking). This covers `ReplicaLike`, `Replica`, `Substrate` and the `merge()` facade. The previous type accepted fields that every implementation ignored.
- **Plain construction** (`@kyneta/schema`) (breaking). `createPlainSubstrate` and `createPlainReplica` are no longer exported; use `plainSubstrateFactory` or `plainReplicaFactory`. The generic `VersionStrategy<V>` is replaced by a concrete `PlainClock`. `create`, `fromEntirety` and promotion are all `upgrade` of a replica. Plain `merge` now takes ops into the doc and log before announcing them, as every other substrate does.

- **The store completes every value it takes** (`@kyneta/schema`, `@kyneta/loro-schema`, `@kyneta/yjs-schema`) (breaking). A value a write carries is completed before it reaches the store: an absent declared field is its zero (`Zero.structural`), an undeclared key is dropped, and a sum holds the variant reads pick. An untyped partial value therefore means "the rest are zeros", and the writer, every receiver and every substrate read the same complete value; before, an untyped partial entry read differently on the writer and on an ephemeral, Loro or Yjs receiver. The delivered op, the plain log and σ carry the completed value. A plain document completes what it merges too, so an entry written under an older schema reads complete after a whole-document or delta merge, while the plain log keeps a merged batch as sent. `tree.create` writes every field of the node's data, partial or absent. The ephemeral substrate drops a value's undeclared keys instead of throwing `The schema has no field "…" to write`. The materializer's sum case is `dispatchSum`, so an unknown discriminant materializes as the first variant instead of throwing.
  - **`buildWritableContext(substrate, schema, capabilities?)`** takes the document's root schema, which `WritableContext.schema` exposes. Authored changes are completed in `prepare`, before any stage, the substrate, the trace, delivery or undo sees them.
  - **`mapPayload(change, f)`** passes each value's slot as `f`'s second argument: a `PayloadSlot`, one of `self`, `item`, `key` or `marks`. A unary `f` is unaffected.
- **A map write costs what it changes** (`@kyneta/schema`, `@kyneta/loro-schema`, `@kyneta/yjs-schema`) (breaking). `mapChangeEffects(change, held)` takes `held` as a thunk, called only for a clear. A record `set` or `delete` enumerated every key of the record in `step`, `invert` and the Loro bridge: one `set` cost 44 µs at 1,000 keys and 620 µs at 10,000 on a plain document. It is now O(|change|), and a clear reads the keys once.
- **A remote change re-materializes only what it touched** (`@kyneta/schema`, `@kyneta/loro-schema`, `@kyneta/yjs-schema`) (breaking). The Loro and Yjs event bridges re-materialized the whole document on every remote batch, and the ephemeral substrate re-projected its whole state on every merge: at 10,000 rows one remote token cost 264 ms on Loro, 10.5 ms on Yjs and 18.7 ms on ephemeral. Every way σ moves apart from an authored write and a plain append is now one reconcile at the parts a change touched (`planReconcile`, `reconcileShadow`, exported for backends): the same token costs 70 µs, 24 µs and 43 µs, and every σ object outside the touched parts keeps its identity. A tick and a plain reset still reconcile at the root.
  - **`diffOps(schema, before, after, path?, keys?)`** diffs a list by position, as one sequence change (retain the common prefix, delete and insert the middle), so a plain reset keeps the addresses of the items it did not move; and with `keys` it diffs only those entries of a record.
  - **`MaterializeResolver.resolveHasKey(path, key)`** is required: whether a record holds a runtime key. `plainResolution.hasKey` and `plainValueResolver(state)`, a resolver over a plain value, are new.
  - **`MergeResult.moved`** (the key path of every node the join moved) replaces `changed`; a merge that moved nothing has `moved.length === 0`.
  - **Structs are completed into schema order**, and a container of the wrong kind completes as its zero, as the materializer reads it, so a writer's and a receiver's serialization of a struct agree on every substrate. A record's key order is unspecified and can differ between peers.
  - `syncShadow` is no longer exported. `touchedBy(ops)` (where each op landed, and how far below it reached) and the `SubtreeEffect` type are.
- **A read is the store's own frozen value, and a write copies only what a read froze** (`@kyneta/schema`, `@kyneta/loro-schema`, `@kyneta/yjs-schema`) (breaking). A value read built a ref for every node it read and kept a second, frozen copy of everything read: `doc.rows()` on a 10,000-row record took about 400 ms and retained 300 MiB. A read is now σ's own value, frozen in place, and builds no refs: the same read takes about 1.3 ms and retains nothing. A write copies a frozen node before changing it, and only on the spine to its target, so a read keeps its identity until a write copies it. The read cache is gone.
  - **Every dead ref reads `undefined`, whatever its kind** — a struct, text or counter included, which read `{ …fields }`, `""` and `0` — though its type does not say so. Ask `deleted(ref)`. A dead list item no longer reads the item that took its index. `${text}` of a dead text ref is still `""`.
  - **`.get(i)` and `.get(key)` read the child from its container's value**, building no ref and freezing only that child. Inside a tracking scope they go through `.at` and the child's `()`, so they report the same dependencies as before.
  - **`bytes` reads are `Uint8Array`s**; they read as plain objects keyed by index before. A read's byte array is the store's own (no typed array can be frozen): copy it before mutating it.
  - **Payloads delivered to subscribers and returned by `batch()` are frozen**, and shared with the store; mutating one throws.
  - **`own(value)` shares a deeply frozen value** rather than copying it, so a read handed back to a write is not copied. A value holding a byte array is always copied.
  - **`applyChanges` owns the ops it is handed**: it shares a payload that is already deeply frozen, copies anything else, and never freezes the caller's objects.
  - **σ lives in a `StateCell`** (`{ current }`, exported), since a write that copies a frozen root replaces it. `plainReader(cell)` and `applyChange(cell, path, change)` take the cell; `reconcileShadow` takes it too. `[NATIVE]` is a getter, so `unwrap(doc)` on a plain document is always the current root.
  - **Read-only stacks complete, and copy**: a read of a partial value returns its completion, and never freezes the caller's data.
  - **Removed**: `withoutTracking`, `writeByPath`, `ownedForStore` (now `freezePayload`, which freezes a payload in place for the store to share), and `WritableContext.preparing`. New exports: `freezePayload`, `freezeTree`, `isDeeplyFrozen`, `StateCell`, and `frozenInvariantViolations` in `@kyneta/schema/testing`.
  - `set.clear()` names the members it removed in its op; the op's `remove` list was the store's own members array, which the clear emptied.
- **An op's path is fixed when the op is made, and a batch keeps one record of what it did** (`@kyneta/schema`, `@kyneta/exchange`) (breaking). Every op a document handed out carried the live addressed path it was prepared at, whose list indices advance as items are inserted before them. A held op replayed to the wrong item, and plain undo of `batch(d => { d.items.at(1).t.set("x"); d.items.insert(0, …) })` wrote another item.
  - **`Op.path` is a `RawPath`**, frozen once, when the op is made: in `batch()`'s return value, in every delivered changeset (rebased), and in `BatchOutcome`. A caller building ops from a ref's `[PATH]` calls `.toRaw()`. Delivery still finds subscribers by identity.
  - **`batch()` returns only the ops that survived**: an inner `batch()` that threw and was caught is no longer in it, so the returned ops replay to the source's state. The changeset still carries the inner writes and their compensations.
  - **An op is recorded once `substrate.prepare` returns**, so a `prepare` that throws is not compensated. `RecordInverseFn` takes only the inverse, and must be called exactly once per forward write (breaking, custom substrates).
  - **A plain aborted batch logs nothing and does not move the version**, and is no local update; a batch that absorbed an inner abort logs only what survived.
  - **Typing groups key by the edited text's position**, so a typing step ends when its list item moves between keystrokes. Authored and native writes now key alike.
  - `SealedBatch.entries` (`{ op, at }`) replaces `SealedBatch.ops`; `authoredSince` and `TraceEntry.authored` are gone. `BatchOutcome.inverses` are `Op`s, and `InverseEntry` is gone. `deliveryConformance`'s local-update check for an aborted batch now asks whether the replica gained ops.

## Removed

- **The unused dismissal plumbing** (`@kyneta/exchange`): the sync program's `ensure-doc-dismissed` effect and the Synchronizer's `onEnsureDocDismissed` callback, which nothing passed, and `Synchronizer.removeDocument` with the `sync/doc-delete` input only it produced. A peer's `dismiss` still clears its per-peer entry; our replica stays.
- **`INVALIDATE`, `ADDRESS_TABLE`, `AddressTableRegistry` and `MapAddressTable`** (`@kyneta/schema`) (breaking). Cache invalidation had nothing left to do once sum addressing became a proxy, and clearing a product's field refs on every write to it gave `doc.outer.mode` a new identity after `doc.outer.set(…)`. A coordinate's address, schema and canonical ref now live on the `CoordinateTrie`.
- **`createNullishStore`** (`@kyneta/react`) (breaking). It had no callers since `useValue` handles `null` and `undefined` itself.
- **The changefeed notification engine is no longer exported** (`@kyneta/schema`). `planNotifications` (now `planDelivery`, internal), `deliverNotifications`, `NotificationPlan`, `attachChangefeed` and `withChangefeed` were public with no importer outside the package. `POPULATED`, `populated` and `populatedFeed` stay exported, as does `expandMapOpsToLeaves` under its new name, `expandProductMapChanges` — `POPULATED` is kept deliberately even though nothing external imports it, because removing a protocol symbol would foreclose implementing that protocol outside the package.

## Fixed

- **A document's store calls run in the order they were made** (`@kyneta/exchange`). A destroy's `delete` was sent outside the store program's order, so on a store that runs calls at once (Postgres, Prisma) it could land before a write already sent, which stored the destroyed document again, and a `get` right after the `destroy` could load what the `delete` removes; `shutdown` did not wait for it either. The Runtime now wraps its Store in `serialStore`, which queues each document's calls; every write is one Store call. `flush` and `shutdown` wait for deletes.
- **No caller value is shared with the store or an op** (`@kyneta/schema`). `push`/`insert`, a map's `set`, a set's `add`, rich-text marks and a tree node's initial data copied nothing, so mutating the object afterwards rewrote the document and the op; a set's `()` returned the store's own array, which changed under the caller on a later `add`. Every value a change carries is now copied at construction and at the store.
- **A remote change to a sequence nested in another sequence keeps ref identity** (`@kyneta/schema`). The address advancement for the inner list ran before the change's path had been resolved, so the ref returned by `items.at(0).tags.at(0)` came to read another item.
- **One ref per coordinate** (`@kyneta/schema`). A product's field refs keep their identity across a replace of the product, and `d.tree.node(id)` (and `.roots`, and iteration) return the same ref while it is held.
- **A ref dies exactly when its coordinate no longer exists** (`@kyneta/schema`). After a replace of a parent, `m.at("k")` returned a ref for a key that was gone; a list item inside a replaced subtree kept its identity; refs nested inside a deleted item stayed alive; and a field of a sum's inactive variant, or of a null nullable, never died. Now a map key, tree node or list item that is gone reports `deleted` and `at()` returns `undefined`; a field dies with its variant; everything below a dead coordinate dies. A key set again, or a variant switched back, revives the same ref, with the refs kept below it.
- **Ephemeral merges and decay ticks, and plain resets, reach subscribers below a top-level field** (`@kyneta/schema`). They announced one `replace` per top-level field that moved, so a subscriber at `peers.alice.cursor` — presence's own use case — never heard a peer move. They now announce the ops a local writer would have produced (`diffOps`): per declared field, record key and register, with a text field as its minimal edit and a counter as an increment. A held `doc.peers.at("alice")` keeps its identity across every merge in which alice exists.
- **A coarse write reaches the subscribers below it** (`@kyneta/schema`). Delivery walked up from a changed path and never down, so `doc.roster.set("alice", {...})` over an existing entry, a struct's `.set`, `m.delete("k")` and `m.clear()` rewrote values without notifying a subscriber at `roster.alice.cursor`, `outer.x` or `m.k`, and a `useValue` of one never re-rendered. A change now reaches the subscribers inside the part of the tree it rewrote, each receiving the change projected onto it (`projectChange`: a `replace` of its new value, or `replace(undefined)` if removed), so a subscriber hears a batch exactly when its read changes identity. `populated(ref)` follows the same rule, so a struct's `.set` populates its fields. Subscribers live in a trie keyed by segment, which also stops two coordinates whose joined path keys collide from sharing subscribers. The tree's delete terminal is now the projection of the delete onto the deleted node, so `synthesizeTreeDeleteTerminal` and the tree's permanent delete-scan registration are gone.
- **`useChangefeed` works over schema composites and over `exchange.peers`/`documents`** (`@kyneta/react`). Over a composite it looped (`current` was new on every read) and missed edits below the node; over a `ReactiveMap` it never re-rendered (`current` was the same live map). It now subscribes as widely as `current` reads, and `current` keeps the identity rule.
- **`useValue`, `useSelector` and `useTracked` keep their value's identity** (`@kyneta/react`). The docs promised stable references between renders and the hooks rebuilt the whole value every render. `useValue` is now `useSelector(ref, readValue)`, and a `React.memo` child given an unchanged part of a value skips re-rendering.
- **`compact()` works for interpreted Yjs and Loro documents** (`@kyneta/exchange`). It threw for them, since a live CRDT substrate cannot trim its history in memory, so their storage was never compacted. The trim moves into `Runtime.compact(docId, trimTo?)`, which trims as far as the replica can (nothing, for a live Yjs or Loro document) and then compacts storage; `Exchange.compact` contributes only the network's bound. A standalone Runtime compacts too, and without a store it trims memory.
- **The least common version never exceeds our own** (`@kyneta/exchange`). During a first contact, a peer's holding is its whole version, concurrent with or ahead of ours until its `accept` arrives, and a compaction then threw. `leastCommonVersion` now starts its meet from our own version.
- **Documents on a wrapped Runtime have `sync()`** (`@kyneta/exchange`). A document created on a standalone Runtime before `new Exchange(runtime, params)` was announced to peers but lacked `sync(doc)` and the peer settle term, so `whenSettled` and `docStatus` ignored the network. New `RuntimeHooks.onDocInterpreted` attaches them for every interpreted document, backfilled like `onDocReady`.
- **Writes made on the native document are synced and persisted** (`@kyneta/exchange`, `@kyneta/schema`, `@kyneta/yjs-schema`, `@kyneta/loro-schema`). A write through `unwrap` never reached a peer or a store: editor bindings (y-prosemirror, y-codemirror, loro-prosemirror), raw `Y.Doc` / `LoroDoc` edits, and Yjs writes to top-level types outside the schema. Each substrate now reports every local write through `subscribeLocalUpdates`, and the Runtime persists and then pushes from that signal, once per document per microtask, instead of from changesets.
- **A destroyed document no longer affects its successor** (`@kyneta/exchange`). Its changeset subscription outlived `destroy`, so writes on the old ref pushed and persisted the new document created under the same id.
- **A local change is persisted once** (`@kyneta/exchange`). A local change reached the store program from both the Runtime and the Synchronizer. `Synchronizer.onStateAdvanced` now reports only network imports.
- **A relay persists the replica it rebuilt** (`@kyneta/exchange`). A replicate-mode reset replaced the replica only in the Synchronizer's copy of the document, so the store kept receiving, and promotion kept wrapping, the replica from before the reset.
- **The Loro bridge no longer throws on a native write to a container the schema does not declare** (`@kyneta/loro-schema`). A root container of the application's own raised "product has no field" inside Loro's event callback; the bridge now skips it.
- **A native write made during a merge keeps its own origin** (`@kyneta/yjs-schema`, `@kyneta/loro-schema`). It used to be labelled with the merge's origin: on Yjs an observer's reaction, on Loro the pending ops an import commits.
- **Concurrent Yjs deletes and inserts converge** (`@kyneta/yjs-schema`, `@kyneta/exchange`). A delete does not advance the Yjs state vector, so a peer that had inserted meanwhile skipped the offer carrying it, and the two peers stayed apart until the deleter wrote again. The Yjs substrate now advances its clock after any change that deleted without inserting, including a plain Yjs client's delete arriving through a parallel provider.
- **A receiver that takes an offer it cannot complete asks for the rest** (`@kyneta/exchange`). A Yjs or Loro receiver missing something the offer depended on, or something its sender held, `accept`ed the offer's version. It now accepts only once its version reaches the offer's, and otherwise asks the sender for what it lacks.
- **An offer's sender is not sent its own changes back** (`@kyneta/exchange`). A push after an import started from before the import, so it carried the import back to the peer that sent it.
- **`YjsVersion` obeys the `Version` laws** (`@kyneta/yjs-schema`). A replica with deletes of its own compared "concurrent" with what it had taken in, and `meet` was not a lower bound.
- **A plain peer that restarts without a store no longer ends up with a corrupted copy** (`@kyneta/schema`, `@kyneta/exchange`). A push could reach it before its catch-up and was appended to an empty log, duplicating entries permanently. A plain delta now says where it starts, and a replica that doesn't hold that point asks for a catch-up instead of applying it.
- **One-way documents are compacted** (`@kyneta/exchange`). A sender never learned what a read-only peer held, so `compact` trimmed nothing and a `Line` outbox's log grew for the life of the Line. Receivers now `accept` each offer.
- **A plain peer that takes a whole document is at the sender's version** (`@kyneta/schema`). Merging one appended a batch, so the receiver's count disagreed with the sender's; relays rebuilt by `fromEntirety` started at count 1. A restarted `Line` receiver no longer sees messages already acknowledged, because the outbox is now compacted.
- **Compacting past a peer that is behind no longer throws** (`@kyneta/schema`). Plain `advance` threw for a target below its trimmed base, although the contract is to trim as far as possible. It now trims nothing.
- **Ephemeral peers catch up on reconnect with a delta** (`@kyneta/exchange`). They quoted their own version as `since`, which the other side could not serve, so it resent the whole document.
- **Writes made while a document loads are persisted** (`@kyneta/exchange`). The store's confirmed version was taken from the in-memory document, so it claimed the loading-time write and every later write skipped it.
- **A reloaded plain document's version matches the store's** (`@kyneta/exchange`). A stored whole-document entry is loaded as the state at its recorded version, rather than as one more batch on top of the log.
- **A document destroyed while loading stays destroyed** (`@kyneta/exchange`). It was re-registered with the Synchronizer once its load finished. `whenHydrated` now rejects for it.
- **A same-document `batch()` from a subscriber is no longer delivered twice on Loro** (`@kyneta/loro-schema`). The inner batch's map writes leaked into the outer commit and were re-announced with `replay: true`.
- **An announcement made during an authored batch no longer takes the batch's ops** (`@kyneta/schema`). A merge inside a `batch()` body, or a native listener writing during a commit, delivered the batch's pending ops labelled `replay: true`.
- **Loro commits aborted batches** (`@kyneta/loro-schema`). Their net-zero compensation ops were left pending and committed with the next batch's origin.
- **Loro recognises every commit issued inside its own batch** (`@kyneta/loro-schema`). A second `exportSince` inside a `batch()` body caused the rest of the batch to be announced again.
- **`BudgetExhaustedError` names the cascade's entry point however deep the cascade nests** (`@kyneta/machine`). The origin stack was cut to V8's default 10 frames, which a nested cascade outgrows; it is now captured whole and rendered with its middle elided.
- **Plain `upgrade` keeps the replica's op log** (`@kyneta/schema`, `@kyneta/exchange`). Promoting a plain replicate document restarted its version at `:0`, so it reported itself behind its own source and could not serve deltas.
- **Plain `fromEntirety` no longer mints a lineage** (`@kyneta/schema`). A document built from a peer's state claimed a fresh identity for content it did not author; it now keeps the payload's lineage, or genesis, until its own first write.
- **A trimmed plain replica no longer corrupts its own state** (`@kyneta/schema`). After `advance`, every rematerialization replayed the retained log onto the base itself, so a list grew by the retained inserts each time the replica was read (`[1,2] → [1,2,2] → [1,2,2,2]`). This affected stores and relays that compact plain documents.
- **An `ephemeral` write always beats what it overwrites** (`@kyneta/schema`). A write overwrote the tuple it replaced, stamped with the wall clock, and nothing checked that the new tuple won the join. When it did not, the writer showed its write while every other peer kept the old value, and once sync ran back the other way the writer adopted the old value too. Three things triggered it: a delete after a set in the same millisecond (reported by Pineta), since a tombstone loses a tie to a live value; a same-millisecond rewrite to a smaller value; and, most seriously, a replica whose clock was behind a value it had already merged, which lost outright with no coincidence needed. Every write is now stamped strictly past whatever it replaces, and never earlier than the wall clock, so a write already past what it overwrites keeps exactly its timestamp. Only the contended nodes move.
- **An `ephemeral` delete reaches what the deleter never saw** (`@kyneta/schema`). A delete tombstoned only the leaves the deleting peer held, so an entry it had never seen, or an inner key another peer wrote before the delete, survived it; deleting an unseen entry could also leave peers disagreeing about the entry's shape, which the merge could not resolve associatively. A delete is now a *horizon*: everything under the key written before it is gone, whoever wrote it, and anything written after it brings the entry back. Deleting an entry of any size ships one tuple.
- **Empty `ephemeral` entries replicate, and so do their deletions** (`@kyneta/schema`). `rooms.set("r1", {})` produced an empty delta, and deleting an empty entry wrote nothing, so the deleting peer showed it gone while every other peer kept it, with equal digests and nothing ever repairing it.
- **A partial `ephemeral` entry reads its missing fields as zeros, and a deleted nested entry stays deleted** (`@kyneta/schema`). A delta carries only the leaves that changed, so a peer can hold an entry with some of its fields; the missing ones read as `undefined`. Separately, deleting an entry that held a nested struct left it visible on other peers. The projection now goes through the schema fold the CRDT backends use, which supplies every zero, and presence is decided by what is actually written beneath a key.
- **Deletes no longer come back as `null`** (`@kyneta/schema`, `@kyneta/exchange`). Building a document from a payload, which `createDoc(bound, payload)` and an exchange promoting a relayed document both do, read the payload's wire shape as the in-memory one. Every tombstone became a live `null`, which then beat the tombstone on every peer it reached.
- **`ephemeral` payloads that cannot be stored are refused** (`@kyneta/schema`). A timestamp of `1e400` parsed as `Infinity`, and any malformed node was accepted. A payload with a malformed node, or a timestamp that is not a non-negative safe integer, is now refused whole before anything changes; the exchange drops it with a warning.
- **A map change naming a key in both `delete` and `set` ends with the key set everywhere** (`@kyneta/schema`, `@kyneta/loro-schema`, `@kyneta/yjs-schema`). `step` set such a key, but the Loro bridge and the changefeed's product expansion deleted it, so Loro's native state disagreed with its own shadow. The Yjs bridge also deleted a struct field under its raw name while setting it under its identity key, so the delete missed. Every consumer now reads map changes through one function, `mapChangeEffects`.

- **`whenSettled` no longer resolves before the authority's state has arrived** (`@kyneta/exchange`). Over a websocket, SSE, or any transport that delivers each frame as its own task, a client's `await whenSettled(doc)` could resolve with `doc()` still empty and `docStatus(doc)` reporting `"empty"` — the entirety merging one task later. Over the in-process bridge the same code was correct only because both frames ran in one turn. The README's two-peer example was the promise being broken. The cause was the sync program marking a peer `synced` on receiving its `interest` whenever `reciprocate` was false, which on a non-bidirectional document is every interest in both directions; that transition also recorded reconciliation, which is what `whenSettled` waits on. An interest now marks its sender `pending`, and `synced` follows only from a version comparison — the same one the offer path already used. `initialize` and `@kyneta/react`'s `useInitialize` inherit the fix. No API change.

- **Changefeed listener registrations follow subscriptions rather than ref carriers** (`@kyneta/schema`). Navigating to a node used to register an own-path listener whether or not anyone subscribed, and nothing ever removed it. Ref carriers were not unique per path — reaching a tree node minted a fresh one each time — so a long-lived document accumulated one permanent registration per carrier ever created, each one an iteration over an empty set on every flush. The cost grew with a document's history instead of with its subscriber count, and it grew fastest for `d.tree.node(id)` inside a subscriber callback, which is a normal thing to write: thirty read-and-write cycles left sixty dead registrations at a single path. Registration now happens on the first subscriber and is released on the last, so navigation is free and unsubscribing really does leave. Delivery is unchanged — same callbacks, same contents.

- **A subscriber registered from inside a callback no longer receives the changeset already in flight** (`@kyneta/schema`). Delivery walked its subscriber set live, and a `Set` visits entries added while it is being iterated, so subscribing during delivery could hand over a batch that was planned and committed before that subscriber existed. Subscribing at a different path in the same callback correctly received nothing, so the two cases disagreed. Both channels now snapshot before delivering, which also means a subscriber unsubscribed by a peer mid-delivery still receives the batch in flight rather than being silently skipped; the unsubscribe takes effect from the next one.

- **Op payloads no longer alias live document state** (`@kyneta/schema`). A `replace` change held whatever the caller passed, and the store wrote that value in by reference — so the op a subscriber received and the subtree inside the document were one object. A later write into that subtree rewrote the op, which then reported a value the batch never made: `d.settings.set({ dark: false })` followed by `d.settings.dark.set(true)` delivered an op reading `dark: true`. Ops were unsafe to hold past the callback, to queue for a later send, or to forward to another document. They are now snapshots and may be kept indefinitely. Writes into large collections got substantially faster as a side effect — a redundant clone in the inverse path was capturing the whole containing collection on every write, and it is gone. This affected all four `PlainState`-backed substrates — plain, ephemeral, and both CRDT backends, whose plain-object shadow is what local reads go through even though their native container tree was never at risk.

- **`whenSettled` and `initialize` honour `Policy.authority`** (`@kyneta/exchange`). `whenSettled` waited for a peer to reconcile whenever *any* transport was configured, ignoring the declared authority — so a server with `authority: "self"` and a transport (the normal shape of a server) hung forever, even though `settled(doc)` and `docStatus(doc)` already reported it settled. In the other direction, a client naming a specific authority resolved on any peer's reply, including another empty client, and `initialize` then returned `"loaded"` for a document the authority had never described. Both came from `whenSettled` keeping its own copy of the rule instead of reading the document's settle term; it now waits on `settledWith(doc, authority)`. `initialize` resolves the authority before the wait rather than after, so an explicit `{ authority }` reaches it. `useInitialize` (`@kyneta/react`) inherits both fixes.
- **The `sync()` API table no longer lists a `settled(opts?)` method** (docs). It was removed in 3.0.0; worse than a stale name, `settled` *is* exported — as a synchronous boolean over a ref, not a promise. The readiness functions now have their own table, and `docs/upgrading-3.0.md` warns about the collision.
- **`canShare` gates the offer that answers a peer's `interest`** (`@kyneta/exchange`). It previously gated only the paths that *announce* or *push* a document, so a peer denied by `canShare` could still obtain the document's full state by requesting it by id — which is what `exchange.get(docId, schema)` does for any document you know the name of. A denied request is now answered `vacant`, the same reply as for a document we do not hold, and no per-peer sync state is recorded. A denied peer's own `present` for a document we hold no longer draws an `interest` reply either, which used to disclose that we had it and at what version.

- **The readiness API is removed** (`@kyneta/exchange`, `@kyneta/react`). Gone: `waitForSync`, `sync(doc).settled()`, `hasSync`, `describeSyncStatus`, `SyncStatusSummary`, `createDerivedSyncStore`. Use `whenSettled(doc)` to wait and `docStatus(doc)` to ask; compose a status label from connectivity + `peerStates` + `docStatus`.
- **`populated(ref)` and `deleted(ref)` return booleans** (`@kyneta/schema`). The `[CHANGEFEED]` carriers are now `populatedFeed` / `deletedFeed`; `isPopulated` and `isDeleted` are removed. **`if (populated(ref))` changes meaning without a compile error** — a carrier is callable, so it was always truthy. Every other use of the pair is a type error until updated.
- **`ephemeral` is a field-level CvRDT** (`@kyneta/schema`). `ephemeral.bind(schema)` still compiles, but each scalar leaf now carries its own `[value, timestamp, deleted?]`, so concurrent writes to different fields both survive instead of the newest snapshot replacing everything. `StateVersion.compare` always reports `"concurrent"`, so no offer is ever discarded as stale. Nothing persists across a restart, which is what `durability: "transient"` always meant. The wire tag changed from `["plain", 1, 0]` to `["ephemeral", 1, 0]`, so 2.x and 3.0 peers cannot sync an ephemeral document — nothing is stored, so nothing needs migrating. `TimestampVersion` and the `buildUpgrade` barrel export are removed with it.
- **`createDoc` no longer takes a peer identity** (`@kyneta/schema`). Use `createDocAs(peerId, bound, payload?)` when identity matters; `createDoc(bound, payload?)` always uses a random one. Replace `createDoc(bound, undefined, "peer-a")` with `createDocAs("peer-a", bound)`.
- **`get()` promotes a replicate document when given its schema** (`@kyneta/exchange`). It previously threw. State accumulated while the document was headless carries across the upgrade.
- **`get()` returns a suspended document without resuming it** (`@kyneta/exchange`). It previously threw. Suspension is sync-graph membership, not local readability, so a read no longer restarts traffic peers can observe.
- **The two schema-compatibility laws are named** (`@kyneta/schema`). `supportsHash` is the primitive; `hashesIntersect` applies it pairwise. `mismatchForInterpretation` answers "can my schema read this document?"; `mismatchForSync` answers "is there a shape we both speak?". `supportedHashes` moves from `DocMetadata` to `ReadCapability` and is required there — a document has one shape, a peer has a set it can cope with.
- **`initialize` and `useInitialize` infer their draft** (`@kyneta/exchange`, `@kyneta/react`). The seed callback now receives the document's type instead of `unknown`. Callers who never named the type parameter gain typing and may find latent mistakes the `unknown` was hiding; callers who wrote `initialize<Foo>(…)` need `Foo` to be the document's type.
- **`Source.of` infers its document and item** (`@kyneta/index`). The accessor receives the real `DocRef` and the key function its item, instead of `any` and `unknown`. Same consequence: previously-unchecked callbacks are now checked.
- **`formatPath` is removed** (`@kyneta/schema`). Use `path.format()`.
- **`advanceSchema`, `findJsonBoundary` and `JsonBoundaryHit` are removed** (`@kyneta/schema`). Use `walkPath`, `findOpaqueBoundary` and `OpaqueBoundaryHit`.
- **`.decay()` below an opaque boundary is rejected at `bind()`** (`@kyneta/schema`). It never worked — a field inside a `sum` or `.json()` blob has no timestamp of its own, so the decay silently never fired. Move `.decay()` onto the sum or `.json()` node itself.

## Added

- **`whenSettled(doc)`, `docStatus(doc)` and `initialize(doc, seed)`** (`@kyneta/exchange`) — wait for every truth source, ask what a document holds, and seed defaults exactly once without overwriting stored data. Settle terms are extensible via a registry.
- **`useDocStatus` and `useInitialize`** (`@kyneta/react`) — the same two, as hooks.
- **`@kyneta/index` reads an exchange.** `Source.fromExchange(exchange, bound)` and `Source.of(...)` build live, incrementally-maintained views over every document matching a schema.
- **`exchange.replicate(docId)`** (`@kyneta/exchange`) — hold a document headlessly, then promote it later by calling `get()` with a schema.
- **`Policy.authority`** (`@kyneta/exchange`) — declare whose answer settles "is this document empty?".
- **Three ephemeral peers in a mesh no longer talk over each other** (`@kyneta/schema`, `@kyneta/exchange`). Opening an ephemeral document on three peers wedged the event loop, with nobody writing anything. Every merge advertised a state change whether or not the join moved, every import was relayed to all peers but the sender, and `StateVersion.compare` can never answer `"equal"` — so nothing declined a payload it already held. Two peers were immune, because excluding the sender leaves nobody to forward to; that is also why every test covering this used two. `mergeStateTree` now reports whether the join moved, and only an import that changed something is relayed.
- **A tombstone no longer ties with a live `null`** (`@kyneta/schema`). The LWW tie-break ranked a leaf by its value, and a tombstone's value is `null` with its marker in a separate slot — so a delete on one peer and a `null` write on another, in the same millisecond, ranked identically and each peer kept its own, diverging permanently and silently through the schema-blind merge that headless relays use. On a tie a live tuple now beats a tombstone.
- **A declared field survives a partial write, and an emptied record still reads as `{}`** (`@kyneta/schema`). The state tree applied one rule to every container — an absent key means "removed" — which is true of a record's keys and false of a struct's fields. A record emptied by deleting its last key vanished from replicated state, and a struct write omitting a field removed it outright. Both were invisible on the peer that caused them, because reads come from a local shadow and only the tree replicates; the field then reappeared from the next peer to sync, since absence carries no information in this merge.
- **Map deletes converge on `ephemeral`** (`@kyneta/schema`). A delete writes a tombstone, so a `Schema.record` used as a presence roster can lose members. Semantics are LWW-Element-Set: a later add beats an earlier delete.
- **`walkPath` / `PathWalk`** (`@kyneta/schema`) — the single schema-guided path traversal. It never throws; it reports where the walk stopped and the caller applies policy.

## Fixed

- **Transient documents never reach durable storage** (`@kyneta/exchange`). A `durability: "transient"` document used to get one empty write at creation, a store read on every open, and a delete on every teardown.
- **Deep subscription survives an unpopulated `.nullable()` field** (`@kyneta/schema`). Subscribing before an optional field was written captured the null variant's changefeed and never heard about writes inside the populated one — permanently. Because the exchange subscribes at creation time, this affected every synced document: the write reached the local substrate but did not replicate until some later unrelated write. `@kyneta/reactive` and React's `useValue` / `useTracked` were affected through the same channel.
- **Writes at or inside a `.nullable()` subtree work on the CRDT backends** (`@kyneta/loro-schema`, `@kyneta/yjs-schema`). They either threw or, on Loro, updated the local shadow while the CRDT never received the write — read back correctly and silently lost on replication.
- **`Schema.record` is usable on `ephemeral`** (`@kyneta/schema`). Every map write threw.
- **Two ephemeral peers writing in the same millisecond converge** (`@kyneta/schema`). The merge resolved timestamp ties by taking the remote value, which is not commutative, so each peer kept its own and neither ever converged — with no error. Which value survives a tie may differ from previous releases; that both peers agree is the fix.
- **The ephemeral substrate no longer decomposes an atomic register when a write targets its interior** (`@kyneta/schema`). Sibling fields the change did not mention were discarded, and replicated state could blend fields across two peers' `sum` variants. Local reads were unaffected, which is what hid it.
- **Schema path-mismatch errors name `stepSchema`**, the function that produces them, rather than a wrapper no traversal calls (`@kyneta/schema`).

## Changed

- **`NotificationPlan` gains a `paths` field** (`@kyneta/schema`), which deep delivery needs to walk ancestors structurally. Additive.

# 2.0.0

**2.0 is a coordinated, breaking release.** All peers must upgrade together — 1.x ↔ 2.0 will not sync — and pre-2.0 on-disk stores belong to a prior epoch: both the schema-hash (`HASH_ALGORITHM_VERSION` → `"02"`) and the new store-format marker reset. Plan/design references are linked as `jj:<id>` for those who want the full rationale; the entries below carry what you need to upgrade.

## Breaking changes — APIs

- **`change(ref, fn)` → `batch(ref, fn)`.** *Migrate:* replace facade `change(...)` calls and `{ change }` imports with `batch`; prefer unwrapping a single mutation to a direct write (`doc.x.set(v)`) over `batch(doc, d => d.x.set(v))`. Same signature and semantics; re-exported under the new name from `@kyneta/schema`, `@kyneta/schema/basic`, `@kyneta/react`, and the Loro/Yjs backends. Since auto-commit-on-write (1.8.0) a single mutation commits on its own, so the facade's job is now batching, not committing. (`jj:rkwspltk`)

- **`SyncProtocol` → `SyncMode`** — it names a per-document sync *mode/policy*, not a wire protocol. *Migrate:* source-level rename — type `SyncProtocol` → `SyncMode`, field `syncProtocol` → `syncMode` (in `DocMetadata`, `bind` configs, `present` metadata), `requiresBidirectionalSync(protocol)` → `(mode)`, the wire helpers (`SyncProtocolWire*` → `SyncModeWire*`, `syncProtocolToWire` → `syncModeToWire`), the validator set `VALID_SYNC_PROTOCOLS` → `VALID_SYNC_MODES`, and the error code `"unknown-sync-protocol"` → `"unknown-sync-mode"`. Re-exported under the new names from `@kyneta/schema` and `@kyneta/exchange`. **No wire bytes change** (the compact key `ms` and its values `0x00`/`0x01`/`0x02` are untouched — a `present` round-trip is byte-identical), and the constants `SYNC_COLLABORATIVE` / `SYNC_AUTHORITATIVE` / `SYNC_EPHEMERAL` are unchanged. The only data effect: persisted metadata key `"syncProtocol"` → `"syncMode"` (operator query path `data->>'syncMode'`), covered by the 2.0 epoch reset. (`jj:yuvupozp`)

- **Sync ready-state vocabulary renamed.** *Migrate:* `ReadyState` → `PeerSyncState` (`.status` → `.state`, `.identity` → `.peer`, value `"absent"` → `"vacant"`); `SyncRef.readyStates` → `peerStates`; `onReadyStateChange` → `onPeerSyncChange`; `Synchronizer.getReadyStates` → `getPeerStates`; React `useSyncStatus` → `useSyncState`. Replace `s.status === "synced"` with `s.state === "synced"`, and prefer `useDocReady(doc)` (below) over deriving a gate from the per-peer array. The never-produced `"unknown"` variant is dropped. Source-level only — no wire/persistence change. (`jj:llosmrmq`)

- **Postgres store takes an injected adapter.** *Migrate:* `createPostgresStore(pool | client)` → `createPostgresStore(fromPool(pool))`, or `createPostgresStore(fromClient(client))` for a single connection. New exports `PgAdapter`, `fromPool`, `fromClient` from `@kyneta/postgres-store`. This also **fixes** the previously-broken bare-`Client` path, which used to throw on `release()`. (`jj:vzuwrotu`)

- **Stores now carry an on-disk format version, and per-doc metadata is renamed `doc_meta`.** *Migrate:* treat pre-2.0 stores as a prior epoch — there is no in-place migration, and a store written under an incompatible format major is now refused on open with a typed error. If you set the SQL `tables` option, rename its key `meta` → `docMeta`. The on-disk names change accordingly (SQL table `kyneta_meta` → `kyneta_doc_meta`, LevelDB key prefix `meta\x00` → `doc-meta\x00`, IndexedDB object store `meta` → `doc_meta`). This is the storage counterpart to the schema-hash epoch reset. (`jj:uvssotsy`)

- **Unix-socket leaderless peer is now a `Transport`, not an `Exchange` consumer.** *Migrate:* `createUnixSocketPeer(exchange, options)` → `createUnixSocketPeer(options)`, then pass it like any transport: `new Exchange({ transports: [peer] })`. `UnixSocketPeer.dispose()` is gone — `exchange.shutdown()` stops it; the `UnixSocketPeer` type becomes `UnixSocketPeerHandle` (`UnixSocketPeerTransport` is also exported). Healing is now in place under one stable `transportId` — the Exchange sees only channel add/remove and all CRDT state survives a heal; the connector defaults to immediate re-negotiation on disconnect (opt into bounded reconnect via `reconnect`). Wire/sync protocol unchanged. (`jj:llpxyzom`)

- **`establish` now carries a required protocol version.** *Migrate:* nothing on the wire — a 2.0 peer's `establish` is byte-identical (an absent version defaults to `(1, 0)`). The field is `EstablishMsg.protocolVersion: { major, minor }` with the `PROTOCOL_VERSION` constant (`@kyneta/transport`, re-exported from `@kyneta/exchange`). Compatibility is a rule, not a negotiation: features differ → silent, `minor` differs → **warning**, `major` differs → **error**. Detection never gates — an incompatible peer stays observable and enters the sync graph (the frozen `SyncRef`/`peerStates` surface is untouched). (`jj:yukrpnwm`)

## Breaking changes — formats

- **All schema hashes change; `HASH_ALGORITHM_VERSION` `"01"` → `"02"`.** *Migrate:* none at the API level — `computeSchemaHash`'s signature and 34-char shape are unchanged; the break is the hash *values*. Redeploy all peers together; 1.x ↔ 2.0 will not sync and a 1.x-persisted `schemaHash` won't match a 2.0 recompute. Canonicalization is now **injective** (field names / constraint values / discriminant keys can no longer forge structural delimiters — e.g. a field named `"a:s:string,b"` no longer collides with two fields `a`/`b`) and includes the `.json()` boundary, so `struct`/`list`/`record` hash distinctly from their `.json()` counterparts. Both were silent sync-incompatibility classes the hash is meant to catch. (`jj:qnmtvtwn`)

## Added

- **Monotonic doc-readiness latch:** `sync(doc).ready` (React `useDocReady(doc)`) flips `true` on first reconciliation — data **or** a terminal `vacant` reply — and never regresses across a reconnect re-handshake or a reconciled peer departing. `sync(doc).readyFor(pred)` / `useDocReady(doc, { peer })` require a matching reconciled peer (authority / quorum). The latch is flicker-free; prefer it over deriving a gate from `peerStates`.
- **`vacant` wire message** (`0x14`, additive): a peer that won't serve a requested doc emits a terminal negative ack; the requester records the peer `vacant` without tearing down its replica. Old peers reject the unknown discriminator harmlessly — wire-backward-compatible.
- **Sync observability:** `sync(doc).connectivity` (`"online" | "connecting" | "offline"`); `sync(doc).settled(opts?)`, which resolves (never rejects) to `{ via: "peer" | "local" | "offline" }`; the pure `describeSyncStatus(peerStates, connectivity, ready)` presentational helper (`@kyneta/exchange`, re-exported from `@kyneta/react`); and React `createDerivedSyncStore`.

## Fixed

- **LevelDB `append` is now atomic** — a single `batch` replaces the separate meta/record puts, so a crash can no longer leave metadata advanced past a missing record. (`jj:pzuytnvo`)

## Packaging

- **`@kyneta/cast` and `@kyneta/compiler` are no longer published.** Both are marked `private` and remain in-repo as experimental (joining `@kyneta/perspective`); they were published at 1.8.0, but there is no 2.0 release of either while they stabilize. (`jj:qyuqnppr`)

## Internal — for substrate & transport authors

- **`SessionEffect`** `{ type: "warning"; message }` → `{ type: "diagnostic"; severity: "error" | "warning"; message }` — the shape the future structured `onProtocolWarning` callback will reuse. Exchange-internal; no application-level or wire change. (`jj:yukrpnwm`)
- **Protocol-version layering:** the sync wire-contract revision (`protocolVersion`) is distinct from `WIRE_VERSION` (frame encoding) and `SyncMode` (per-doc policy). Additive evolution rides `WireFeatures`; `protocolVersion` carries only the one thing features can't express (base abandonment). On the wire it's sparse — `pv: [major, minor]` only when non-default. New `Synchronizer` surface: `declareVacant` / `hasReconciled` / `reconciledMatching` / `connectivity`. (`jj:yukrpnwm`, `jj:llosmrmq`)

Canonicalization (`canonicalTuple`, arrays + strings only) carries a recursion depth cap that throws a clear error on an `as any`-forced cyclic schema graph (the grammar otherwise guarantees finite, eager, acyclic trees; recursive *data* uses `Schema.tree`). (`jj:qnmtvtwn`)

- **Unix-socket cleanup (no consumers):** removed `UnixSocketClientTransport.subscribeToTransitions`, the `UnixSocketClientStateTransition` type, and the unused `UnixSocketServerTransport` helpers (`getConnection` / `getAllConnections` / `isConnected` / `broadcast`); the low-level `UnixSocketConnection` constructor is now `(socket)`. # 1.8.0

  Schema — three-primitive substrate contract:
  - The transaction lifecycle (`beginTransaction` / `commit` / `abort` / `inTransaction` / `pending`) is removed from `WritableContext`. `change(doc, fn)` is now a thin wrapper around `ctx.runBatch` (a `runWriter` / `execWriter` pattern over the change-Writer monad). The public `change(doc, fn)` and `applyChanges(ref, ops)` APIs are unchanged. **Breaking** for code that constructed `WritableContext` by hand (test fixtures) or called `ctx.beginTransaction` / `ctx.commit` / `ctx.abort` directly.

The change algebra is a groupoid; abort is identity composition `c ∘ c⁻¹ = id`, not state rollback.

# 1.7.0

  Schema — tree and set algebras realized end-to-end:
  - `Schema.tree` now works end-to-end on Loro. The write API ships `.create(id, parent, index, data?)`, `.move(id, parent, index)`, and `.delete(id)`; reads expose `.roots`, `.node(id)`, depth-first iteration, and a callable snapshot. Subscribers on `tree.node(id).field` receive precise notifications. Previously a manually-constructed `TreeChange` failed with *"unsupported change type 'tree'"* and Loro events at tree nodes arrived at the changefeed without their `TreeID`.
  - `Schema.set` is now value-addressed end-to-end. `SetRef<I>` exposes `.has(value)`, `.add(value)`, `.delete(value)`, `.clear()`, `.size`, `[Symbol.iterator]` over plain values, and is callable returning `Plain<I>[]`. For object-typed items, `.has(value)` uses content equality. There are no per-member child refs — sets are ref-layer leaf-shaped, not keyed-shaped.

  **Breaking — schema type shapes:**
  - `Plain<TreeSchema<I>>` is now `FlatTreeNode<Plain<I>>[]` (was incorrectly `Plain<I>`). `Zero` of a tree is `[]`. JSON-roundtrip a tree as a flat node array.
  - `Plain<SetSchema<I>>` is now `Plain<I>[]` (was inconsistently `Plain<I>[]` at the type level but produced `Record<string, V>` at runtime). Storage, materialize, zero, and reader all agree on the array shape.
  - `TreeSchema.nodeData` → `TreeSchema.item` for parity with every other container kind (`sequence.item`, `map.item`, `set.item`, `movable.item`).
  - `tree-position` module → `doc-position`: `resolveTreePosition` → `resolveDocPosition`, `flattenTreePosition` → `flattenDocPosition`, `ResolvedTreePosition` → `ResolvedDocPosition`. The algebra operates over a rooted document, not arbitrary schema trees, and the rename frees "tree" for the CRDT primitive.
  - Changefeed cluster: `subscribeTree` → `subscribeDescendants`, `TreeChangefeedProtocol` → `RecursiveChangefeedProtocol`, `HasTreeChangefeed` → `HasRecursiveChangefeed`, `hasTreeChangefeed` → `hasRecursiveChangefeed`. *This supersedes the `ComposedChangefeed*` → `TreeChangefeed*` rename from 1.6.0 — apologies for the consecutive churn; "Tree" is now reserved for the CRDT primitive, and `subscribe(Node|Descendants)` names the shallow/deep semantic without overloading the noun.*
  - `Segment.role` renormalized: `"key" | "index"` → `"field" | "entry" | "index"` (declared product field / runtime string key / runtime numeric index). Identity-keying applies at `seg.role === "field"` boundaries — purely segment-local, no parent-kind sniff. `Path.node(id)` is sugar over `Path.entry(id)`; `Path.field(name)` is reserved for declared product field names. App code that goes through the schema API is unaffected; if you constructed `Path`/`Segment` values directly, update role tags.

  Wire — protocol v2 (**protocol-breaking, lockstep upgrade required**):
  - `WIRE_VERSION` 1 → 2. Binary fragmentation now slices unframed payload bytes rather than framed bytes, saving 6 bytes per fragmented message and eliminating the receiver's double-decode. v1 Fragment frames from older peers produce a typed `unsupported_version` error. Complete frames (the 99% case) remain byte-identical. **Both peers must upgrade in lockstep.**
  - Asymmetric SSE encoding. Client uploads switch from JSON-over-text/plain to raw CBOR over `application/octet-stream`. Server downstream stays text JSON (substrate-forced). Eliminates the ~33% base64 bandwidth tax on `SubstratePayload.bytes`. Bundled with the SSE upgrade.
  - Trust boundary at the decoder. Every wire message is now shape-validated after CBOR/JSON parse via `validateWireMessage`. Malformed or hostile peer messages surface as typed `invalid-wire-message` errors through `Pipeline.onError` instead of crashing the channel or corrupting CRDT state. Identifier byte-length caps are enforced at insert time on the alias map; feature gates in `establish` use strict `=== true`.

  Wire / Transport — `Pipeline` unification:
  - One `Pipeline<S, R>` class replaces seven near-mirror assembly sites across WebSocket, WebRTC, SSE, Unix socket, and Bridge transports. Per-transport send/receive collapses to three lines plus I/O. The same class covers both binary and text substrates and supports asymmetric encodings (the SSE case above). `@kyneta/wire` becomes a leaf — concrete transport packages now import wire-derived symbols via `@kyneta/transport`. No drift between transports.
  - One `Reassembler<T>` replaces `FragmentReassembler` + `TextReassembler`; one `fragmentGeneric<T>` chunk loop replaces `fragmentPayload` + `fragmentTextPayload`.

  - 3-peer relay regression: synchronizer now owns the `channelId` namespace, fixing a regression in which relay topologies (peer A ↔ relay ↔ peer B + peer C) misrouted channel traffic.

  - Wire version field: encoders now reject `version` values outside the encodable range up front.

# 1.6.1

  Fixes:
  - Schema (discriminated unions): cache-invalidation handlers no longer accrete on repeated variant flips. Sum fields register invalidation handlers on both the parent product and the active variant product; the previous shape stored them in a left-folded closure keyed only by path, so re-interpreting a sum's current variant after each cache flush accumulated dead handlers (eventually risking a stack overflow via composed recursion). Handlers are now keyed by registrant path and replace on re-registration. No API change.
  - Substrate event bridge (Loro / Yjs): re-entrant writes during event-bridge replay are no longer silently dropped. Previously, when a remote sync payload was merged and a user subscriber wrote back to the doc inside the replay, the write reached the changefeed layer but was dropped at the native CRDT — producing an infinite re-delivery loop bounded only by `BudgetExhaustedError`. The bridge now uses a structural `replay` flag instead of a global re-entrancy guard.
  - Exchange echo suppression: `origin` is yours again. The Exchange previously used the string `"sync"` on `Changeset.origin` as its own control signal for suppressing local broadcast. This had two failure modes: (1) user code calling `change(doc, fn, { origin: "sync" })` accidentally suppressed broadcasts; (2) external Loro batches whose origin was not the literal string `"sync"` could echo back to peers. Echo suppression is now keyed on a structural `replay: true` flag in `BatchOptions`, leaving `origin` free for application use.

  **Migration note (if affected):** if any code passed `origin: "sync"` to `change()` to suppress broadcast, switch to `change(ref, fn, { replay: true })`. Application-defined origin strings (`"local"`, `"undo"`, `"llm"`, etc.) work exactly as before and now reliably don't collide with internal sync behavior.

  Diagnostics:
  - `BudgetExhaustedError` is actionable. The error now carries (a) the cascade's entry-point stack frame — typically your `change()` site or the transport boundary that opened the dispatch — (b) a histogram of the top message types contributing to the cascade, and (c) tick-deduplicated history so the recent-events tail shows real subscriber-driven work instead of routing housekeeping. When you hit a runaway, the error tells you which subscriber pair is oscillating.

  Internal:
  - `BatchOptions { origin, replay }` replaces the bare `origin` string at the substrate `prepare/flush` boundary. No public API change for `change()` callers other than the new `replay` flag.

# 1.5.2

  Fixes (no action required):
  - Index: materialized views built from `Source.union`, `Source.map`, or `Source.filter` no longer silently lose entries under composition.
